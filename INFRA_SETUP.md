# Инструкция для агента: покупка сервера и домена, настройка Coolify

Ты — агент, работающий в браузере от имени владельца проекта. Твоя задача — подготовить
инфраструктуру для деплоя админ-панели Base40 (репозиторий GitHub
`borinsobaka-lab/club-40-hub`). Выполняй шаги строго по порядку: каждый следующий шаг
зависит от предыдущего. Ничего не удаляй и не отменяй без подтверждения владельца.

## Что понадобится от владельца (запроси заранее)

1. Платёжное средство (карта / PayPal) для Hetzner и регистратора домена.
2. Желаемое имя домена и потолок цены (ориентир: 10–15 $/год).
3. Доступ к GitHub-аккаунту `borinsobaka-lab` (для подключения репозитория к Coolify).
4. Доступ к Supabase Dashboard проекта (для ключей и настроек Auth).
5. E-mail для регистраций: borin.sobaka@gmail.com (или другой по указанию владельца).

Все созданные логины/пароли сразу сохраняй в менеджер паролей владельца и включай 2FA,
где это возможно. Секретные ключи никуда не вставляй, кроме указанных в инструкции полей.

---

## Шаг 1. Сервер Hetzner Cloud

1. Зайди на https://console.hetzner.com (Hetzner Cloud Console). Если аккаунта нет —
   зарегистрируйся на https://accounts.hetzner.com с e-mail владельца.
   Учти: Hetzner может запросить подтверждение личности/платёжного средства у новых
   аккаунтов — в этом случае привлеки владельца.
2. Создай проект, например `club40`.
3. В проекте нажми **Add Server** и выбери:
   - **Location**: Falkenstein (fsn1) или Helsinki (hel1) — что доступно.
   - **Image**: Ubuntu 24.04.
   - **Type**: Shared vCPU (x86) → **CX32** (4 vCPU / 8 GB RAM / 80 GB SSD, ~8 €/мес).
     Если CX32 недоступен — CPX31. Меньше 8 GB RAM не бери: на сервере будут Coolify
     и два приложения.
   - **Networking**: включены и IPv4, и IPv6.
   - **SSH key**: если владелец дал публичный ключ — добавь; если нет — пропусти
     (root-пароль придёт на e-mail, сохрани его в менеджер паролей).
   - **Cloud config / User data**: вставь ровно этот текст — он сам установит Coolify
     при первой загрузке:

     ```yaml
     #cloud-config
     runcmd:
       - curl -fsSL https://cdn.coollabs.io/coolify/install.sh | bash
     ```

   - **Name**: `club40-coolify`.

4. Создай сервер, дождись статуса Running и запиши его **IPv4-адрес** — он нужен всюду
   дальше (далее обозначен как `<IP>`).
5. Подожди 5–10 минут (идёт установка Coolify) и проверь, что открывается
   `http://<IP>:8000`. Если через 15 минут не открывается — сообщи владельцу, не
   пересоздавай сервер сам.

## Шаг 2. Домен

1. Купи согласованное с владельцем имя у регистратора (рекомендуется https://porkbun.com,
   альтернатива — https://www.namecheap.com): найди домен через поиск, оформи покупку на
   e-mail владельца. WHOIS-privacy оставь включённым (у Porkbun бесплатно). Автопродление
   включи.
2. В DNS-панели регистратора создай A-записи (TTL по умолчанию), все — на `<IP>`:

   | Тип | Имя       | Значение |
   | --- | --------- | -------- |
   | A   | `coolify` | `<IP>`   |
   | A   | `admin`   | `<IP>`   |
   | A   | `app`     | `<IP>`   |

   (`app` — задел под клиентское приложение, вторая итерация.)

3. Проверь распространение DNS на https://dnschecker.org: `coolify.<домен>` и
   `admin.<домен>` должны отдавать `<IP>`. Обычно это минуты, максимум пара часов.

## Шаг 3. Первичная настройка Coolify

Выполняй сразу после того, как заработал `http://<IP>:8000` — пока порт открыт,
зарегистрироваться первым может кто угодно.

1. Открой `http://<IP>:8000` → **Register**: создай первого админа (e-mail владельца,
   сгенерированный пароль → в менеджер паролей).
2. В онбординге выбери **Localhost** (Coolify управляет тем же сервером, где установлен).
3. **Settings → Instance Settings**: в поле Domain укажи `https://coolify.<домен>`,
   сохрани. Дождись выпуска SSL-сертификата и проверь, что панель открывается по
   `https://coolify.<домен>`.
4. Вернись в консоль Hetzner: **Firewalls → Create Firewall**:
   - Inbound-правила: TCP 22, TCP 80, TCP 443, ICMP — источник Any.
   - Порт 8000 в правила НЕ включай — панель теперь доступна только через домен.
   - Примени файрвол к серверу `club40-coolify`.
5. Проверь: `http://<IP>:8000` больше не открывается снаружи, `https://coolify.<домен>`
   работает.

## Шаг 4. Подключение GitHub

1. В Coolify: **Sources → + Add → GitHub App**. Следуй мастеру: он отправит на GitHub
   создать GitHub App и установить его. Понадобится вход в аккаунт `borinsobaka-lab`.
2. При установке App выдай доступ к репозиторию `club-40-hub` (можно "Only select
   repositories").

## Шаг 5. Деплой админки

1. В Coolify создай **Project** `club40`, внутри — **+ New Resource →
   Private Repository (with GitHub App)** → выбери `borinsobaka-lab/club-40-hub`,
   ветка `main`.
2. Настройки приложения:
   - **Build Pack**: Dockerfile. С 2026-10-10 репозиторий — монорепозиторий:
     **Base Directory** `/`, **Dockerfile Location** `/apps/admin/Dockerfile`,
     **Watch Paths** `apps/admin/**` и `db/**` (см. AGENT_TASKS.md, Задача 9).
   - **Port**: 3000.
   - **Domain**: `https://admin.<домен>`.
3. **Environment Variables** — добавь три переменные:

   | Имя                             | Значение                                                               | Особенность                              |
   | ------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------- |
   | `VITE_SUPABASE_URL`             | `https://api.base40.fit`                                               | отметь галочку **Build Variable**        |
   | `VITE_SUPABASE_PUBLISHABLE_KEY` | значение из файла `.env` в репозитории (anon-ключ, начинается с `eyJ`) | отметь галочку **Build Variable**        |
   | `APP_SUPABASE_SERVICE_KEY`      | service_role JWT self-hosted Supabase (Coolify → ресурс Supabase)      | runtime-секрет, галочку Build НЕ ставить |

   Переменные AI (`AI_GATEWAY_*`, `AI_CHAT_MODEL`, `AI_TRANSCRIBE_MODEL`) сейчас
   задавать НЕ нужно: ассистент и диктовка сознательно отключены до выбора провайдера.

4. Нажми **Deploy** и дождись успешной сборки (первая занимает несколько минут).
   Включи автодеплой по push в `main` (Auto Deploy), если не включён по умолчанию.
5. Проверь, что `https://admin.<домен>` открывается и показывает страницу входа.

## Шаг 6. Настройка Supabase Auth

1. Зайди в Supabase Dashboard проекта → **Authentication → URL Configuration**:
   - **Site URL**: `https://admin.<домен>`.
   - **Redirect URLs**: добавь `https://admin.<домен>/**`.
   - Старые lovable-адреса пока НЕ удаляй — они нужны, пока живёт старая версия.

## Шаг 7. Проверка (смоук-тест)

Пройди по `https://admin.<домен>` и проверь:

1. Вход по логину/паролю работает.
2. Открываются разделы: Дашборд, Клиенты, Расписание, Абонементы, Продажи, Касса,
   Сотрудники, Новости, Пуши.
3. Загрузка фото/аватарки работает (Supabase Storage).
4. AI-ассистент и голосовая диктовка должны показать сообщение «временно недоступен» —
   это ожидаемо, НЕ ошибка.
5. В разделе «Сотрудники» список загружается (проверка серверного ключа
   `APP_SUPABASE_SERVICE_KEY`).

## Шаг 8. Отчёт владельцу

Собери и передай владельцу:

- IP сервера, тип сервера, локация, стоимость/мес.
- Купленный домен, регистратор, стоимость/год, дата продления.
- Адреса: панель Coolify, админка.
- Где сохранены все созданные пароли; статус 2FA по каждому сервису.
- Результаты смоук-теста по пунктам шага 7.
- Что НЕ делалось: отключение Lovable (шаг 9 — только по отдельной команде владельца).

## Шаг 9. Отключение Lovable от репозитория (ТОЛЬКО по отдельной команде владельца)

Не выполняй этот шаг в одном заходе с шагами 1–8. Он делается после того, как владелец
проверил новую админку на своём домене и явно сказал «отключай Lovable».

1. GitHub (зайди под аккаунтом `borinsobaka-lab`): аватар → **Settings** →
   **Applications** (раздел Integrations) → вкладка **Installed GitHub Apps** →
   найди приложение **Lovable** (может называться **GPT Engineer App**; его бот
   в коммитах — `gpt-engineer-app[bot]`) → **Configure** → внизу **Uninstall**
   (или в Repository access убери `club-40-hub` и сохрани, если приложение
   используется другими проектами владельца). После этого Lovable теряет доступ
   к репозиторию.
2. Lovable (lovable.dev, аккаунт владельца): открой проект админки → Settings →
   раздел GitHub → Disconnect (если после п. 1 связь ещё отображается).
3. Там же в Lovable: **Unpublish** опубликованного сайта админки — только если
   владелец подтвердил, что новая версия на своём домене работает.
4. Подписку Lovable не отменяй сам — напомни владельцу сделать это после того,
   как оба приложения (админка и клиентское) переедут.

Отключение синхронизации с GitHub само по себе не выключает опубликованный сайт
Lovable — это безопасная операция, код уже полностью в репозитории.

## Чего делать нельзя

- В рамках шагов 1–8: не удаляй и не отключай ничего в Lovable и не меняй настройки
  GitHub-репозитория (шаг 9 — отдельная команда владельца).
- Не удаляй существующие Redirect URLs в Supabase.
- Не публикуй и не пересылай `service_role`-ключ и пароли в открытом виде.
- Не покупай дополнительные услуги (бэкапы, балансировщики, почту) без согласования.
