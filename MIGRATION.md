# План миграции с Lovable на собственную инфраструктуру (Hetzner + Coolify)

Дата: 2026-08-06. Репозиторий: `borinsobaka-lab/club-40-hub` (админка).

## Что показал аудит кода

Хорошая новость: **вся «начинка» уже наша**. Auth, база, RLS-политики, storage — всё в личном
Supabase (на момент аудита — облачный `lyvarbqquvgxufmqgyix.supabase.co`; с 2026-10-07 —
self-hosted в Coolify, API `https://api.base40.fit`), схема БД версионируется в `db/*.sql`. Данные
переносить не нужно вообще. От Lovable зависят только четыре вещи:

| #   | Зависимость                                                                                                                   | Где                                                                                                                                                                            | Что делать                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 1   | `@lovable.dev/vite-tanstack-config` — обёртка над всем Vite/Nitro-конфигом (собирает под Cloudflare, включает их dev-плагины) | `vite.config.ts`, `package.json`                                                                                                                                               | Заменить на явный конфиг: TanStack Start + React + Tailwind + tsconfig-paths + Nitro с пресетом `node-server`             |
| 2   | **Lovable AI Gateway** (`ai.gateway.lovable.dev`, ключ `LOVABLE_API_KEY`)                                                     | `src/lib/ai-gateway.server.ts`, `src/routes/api/chat.ts` (ассистент, модель `google/gemini-3-flash-preview`), `src/routes/api/transcribe.ts` (`openai/gpt-4o-mini-transcribe`) | Перевести на прямого провайдера. Ассистент и диктовка перестанут работать в момент разрыва с Lovable, если это не сделать |
| 3   | Отчёты об ошибках в Lovable-редактор (`window.__lovableEvents`)                                                               | `src/lib/lovable-error-reporting.ts`, `src/routes/__root.tsx`                                                                                                                  | Удалить (вне Lovable это no-op); при желании позже заменить на Sentry                                                     |
| 4   | Косметика: `.lovable/`, блок в `AGENTS.md`, исключения в `bunfig.toml`, og:image на `*.lovable.app`                           | корень репо                                                                                                                                                                    | Вычистить                                                                                                                 |

Плюс сам хостинг: сейчас приложение опубликовано на Lovable, git синхронизируется в этот репозиторий.

## Порядок действий

### Этап 1 — подготовка кода (✅ выполнено в этой ветке)

1. Убрать `@lovable.dev/vite-tanstack-config`, написать обычный `vite.config.ts`
   (сохранив alias `lucide-react → src/lib/icons.tsx` и server entry `src/server.ts`),
   Nitro-пресет `node-server`.
2. AI-гейтвей: **решение владельца — новый провайдер пока не подключаем.**
   Код Lovable-гейтвея заменён на провайдер-агностичную заглушку
   (`src/lib/ai-gateway.server.ts`): пока в окружении не заданы
   `AI_GATEWAY_BASE_URL` / `AI_GATEWAY_API_KEY` / `AI_CHAT_MODEL` /
   `AI_TRANSCRIBE_MODEL`, ассистент и диктовка отвечают 503 «временно недоступно».
   Подключение реального провайдера (OpenAI / Google / OpenRouter) — отдельная задача
   после переезда: достаточно задать эти четыре переменные в Coolify.
3. Удалить lovable-error-reporting и косметику (п. 3–4 таблицы).
4. Добавить `Dockerfile` (bun install → vite build → запуск `.output/server/index.mjs`, порт 3000) и `.dockerignore`.
5. Проверить локально: `bun run build` и запуск продакшен-сборки.

Результат этапа: репозиторий собирается и работает без единого упоминания Lovable.
Lovable при этом ещё жив — откатиться можно в любой момент.

### Этап 2 — инфраструктура

> Пошаговая инструкция для агента, который будет выполнять этот и следующий этапы
> в браузере, — в файле `INFRA_SETUP.md`.

1. **Сервер Hetzner Cloud**: рекомендация — **CX32 (4 vCPU / 8 GB / 80 GB), ~8 €/мес**,
   Ubuntu 24.04 LTS, локация Falkenstein или Helsinki. Этого хватит на Coolify + админку +
   клиентское приложение. Масштабирование — штатный Rescale в панели Hetzner (CX42/CX52 и выше)
   за пару минут; если не увеличивать диск, можно и уменьшаться обратно. Позже Coolify умеет
   подключать дополнительные серверы по SSH — горизонтальный рост тоже закрыт.
2. **Домен**: любой регистратор (Porkbun / Namecheap / Cloudflare Registrar, ~10–12 $/год).
   DNS удобно держать в Cloudflare (бесплатно). Записи:
   - `admin.<домен>` → A → IP сервера (админка)
   - `app.<домен>` или корень → A → IP сервера (клиентское, итерация 2)
   - `coolify.<домен>` → A → IP сервера (панель Coolify)
3. **Базовая защита сервера**: вход только по SSH-ключу, Hetzner Cloud Firewall
   (открыты 22, 80, 443; порт 8000 закрыть после привязки панели к домену с SSL).
4. **Установка Coolify** (self-hosted, бесплатно):
   `curl -fsSL https://cdn.coollabs.io/coolify/install.sh | bash`,
   затем в UI привязать `coolify.<домен>` с автоматическим Let's Encrypt.

### Этап 3 — деплой админки

1. В Coolify подключить GitHub (GitHub App) → выбрать `club-40-hub`, сборка по Dockerfile,
   автодеплой по push в `main`.
2. Переменные окружения:
   - `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` — нужны **на этапе сборки** (build args)
   - `APP_SUPABASE_SERVICE_KEY` — runtime-секрет (серверные функции раздела «Сотрудники»)
   - AI-переменные пока не задаём (ассистент сознательно отключён до выбора провайдера)
3. Привязать `admin.<домен>`, SSL выдаст сам Coolify.
4. В Supabase → Authentication → URL Configuration добавить `https://admin.<домен>`
   в Site URL / Redirect URLs (иначе логин и magic-ссылки не заработают).
5. Смоук-тест: логин, все разделы, ассистент, голосовая диктовка, загрузка аватаров,
   расписание/бронирования.

### Этап 4 — разрыв с Lovable (только после того, как этап 3 проверен)

1. В Lovable: Unpublish сайта, отключить GitHub-интеграцию, отменить подписку
   (при желании удалить проект — репозиторий остаётся единственным источником правды).
2. `LOVABLE_API_KEY` умирает вместе с проектом — к этому моменту он уже нигде не используется.

### Этап 5 — итерация 2: клиентское приложение

Тем же маршрутом: этап 1 (чистка кода) → деплой вторым приложением в Coolify на
`app.<домен>` → перенастройка Redirect URLs в Supabase → разрыв его связи с Lovable.
Инфраструктура уже готова, поэтому итерация 2 — это только код и деплой.

## Бюджет

- Сервер: ~8 €/мес (CX32), рост до ~17 €/мес (CX42) при необходимости
- Домен: ~10–12 $/год
- Coolify: 0 (self-hosted)
- OpenAI API: по факту использования ассистента (копейки на этих моделях)
- Supabase: как сейчас, ничего не меняется

## Риски и заметки

- Переключение бесшовное: новый прод поднимается параллельно живому Lovable,
  DNS-переезд мгновенный, откат — тоже.
- AI-ассистент и диктовка после переезда сознательно отключены (отвечают «временно
  недоступно») до выбора нового провайдера — это решение владельца, не ошибка.
- База остаётся в облачном Supabase — это правильно на текущем этапе; self-host Supabase
  на тот же Coolify возможен позже, но сейчас только добавит рисков.
