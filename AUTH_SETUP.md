# Настройка почтовой авторизации (noreply@base40.fit)

Письма разделяются **по приложению, а не по человеку**. Админка и клиентское
приложение — разные сущности: один и тот же человек может быть и
администратором, и клиентом, и в клиентском приложении он должен идти
клиентским путём.

Отправку писем Supabase делегирует нашему серверу (Send Email Hook →
`https://admin.base40.fit/api/auth-email`), который смотрит, из какого
приложения пришёл запрос, и шлёт через **Resend** (`RESEND_API_KEY` у
club40-admin). Unisender Go отключён (решение владельца 2026-10-11):

- вход в **клиентское приложение** (app.base40.fit) → **6-значный код**,
  без единой ссылки — даже если это администратор;
- вход в **админку** (admin.base40.fit) → **ссылка авто-входа**, без кода;
- восстановление пароля и приглашения сотрудников — письма со ссылками
  (у клиентов паролей нет, эти сценарии только в админке).

Признак приложения — адрес возврата, который приложения передают явно. Если
распознать не удалось, отправляется код: ссылка авто-входа — это полный
доступ, и слать её «на всякий случай» нельзя.

Редактировать шаблоны в Supabase НЕ нужно — при включённом хуке они не
используются. Код обоих приложений готов; ниже — шаги настройки.

## Шаг 1. Resend

1. Домен `base40.fit` в Resend (resend.com → Domains) — статус **Verified**:
   DKIM `resend._domainkey`, SPF и MX на `send.base40.fit` в Cloudflare DNS.
   Иначе письма не уйдут (Resend ответит 403) или упадут в спам.
2. API-ключ Resend (API Keys → Create API Key, Permission: Sending access,
   Domain: **All domains** — ключ шлёт и с `base40.fit`, и с
   `lady-stretch.one`).
3. Домен `lady-stretch.one` (письма клиентам пакетных клубов, с 2026-10-15) —
   тоже **Verified**, записи — у регистратора `lady-stretch.one`; после этого
   у club40-admin `LADY_STRETCH_MAIL_FROM=noreply@lady-stretch.one`
   (AGENT_TASKS.md, Задача 13). Без переменной письма Lady Stretch уходят с
   `noreply@base40.fit` под именем «Lady Stretch».

Бесплатного тарифа Resend (3000 писем в месяц, 100 в день) хватает на коды
входа на время тестов; при большем числе клиентов — тариф Pro.

## Шаг 2. Секрет хука в Supabase

Supabase self-hosted (Coolify, API `https://api.base40.fit`): Dashboard с
разделом Hooks нет, хук задаётся переменными сервиса **auth** (GoTrue).

1. Сгенерировать секрет: `echo "v1,whsec_$(openssl rand -base64 32)"`.
   (Если секрет уже стоит у club40-admin в `SEND_EMAIL_HOOK_SECRET` — взять его.)
2. **ПОКА НЕ включать** хук — сначала шаг 3.

## Шаг 3. Переменные в Coolify

Coolify → приложение **club40-admin** → Environment Variables, добавить две
runtime-переменные (галочку Build Variable НЕ ставить):

| Имя                      | Значение                          |
| ------------------------ | --------------------------------- |
| `SEND_EMAIL_HOOK_SECRET` | секрет из шага 2 (`v1,whsec_...`) |
| `RESEND_API_KEY`         | API-ключ из шага 1 (`re_...`)     |

Затем **Restart** приложения.

## Шаг 4. Включить хук

Coolify → ресурс Supabase → сервис **auth** → Environment, добавить:

```
GOTRUE_HOOK_SEND_EMAIL_ENABLED=true
GOTRUE_HOOK_SEND_EMAIL_URI=https://admin.base40.fit/api/auth-email
GOTRUE_HOOK_SEND_EMAIL_SECRETS=<секрет из шага 2, v1,whsec_...>
```

и перезапустить сервис auth. С хуком SMTP в Supabase не нужен.
Порядок важен: если включить хук до рестарта админки с переменными, письма
перестанут уходить вовсе (роут ответит 500).

## Шаг 5. Длина кода

Приложение рассчитано на 6 цифр. Проверьте `GOTRUE_MAILER_OTP_LENGTH`
(не задан = 6) и `GOTRUE_MAILER_OTP_EXP` (3600 сек достаточно).

## Шаг 6. Лимиты

`GOTRUE_RATE_LIMIT_EMAIL_SENT` у сервиса auth — **3000** (писем в час на
весь сервер, оба приложения и админка вместе; по умолчанию GoTrue — 30).
Лимит действует и при хуке писем: при 100 в час (прежняя рекомендация) в
утро запуска большинство клиентов получили бы «Слишком часто» вместо кода.
От перебора защищает предел на адрес (`GOTRUE_SMTP_MAX_FREQUENCY`, раз в
минуту) и `GOTRUE_RATE_LIMIT_VERIFY` — их не трогать. Resend — тариф Pro:
на бесплатном 100 писем в сутки (LAUNCH_READINESS.md, 2026-10-16).

## Шаг 7. Проверка

1. Клиентское приложение (app.base40.fit и app.lady-stretch.one), почтой
   клиента, который заведён на портале → «Получить код» → письмо от
   `Base40 <noreply@base40.fit>` с 6 цифрами и без ссылок → вход работает,
   дальше — онбординг.
2. Почта, которой нет ни в одной карточке клиента → «Получить код» →
   на экране «Эта почта не найдена среди членов клуба», письма нет.
   Регистрации в приложении нет (решение владельца 2026-10-11).
3. Админка → почта сотрудника → письмо «Вход в админ-панель» с кодом →
   вход.
4. Письма не в спаме.

Если письма перестали приходить: Coolify → club40-admin → Logs, искать
`[auth-email]` и `[mail]` (там ответ Resend, например `Resend 403: domain is
not verified`); resend.com → Emails — ушло ли письмо и что ответил почтовый
сервер получателя. Откат — `GOTRUE_HOOK_SEND_EMAIL_ENABLED=false` (но без
настроенного SMTP встроенные письма Supabase уходить не будут).

## Как это устроено (для справки)

Роут `apps/admin/src/routes/api/auth-email.ts` проверяет подпись вебхука
(HMAC, standardized-webhooks); логика писем — `apps/admin/src/lib/auth-email.ts`,
покрыта тестами (`bun test`): решение принимается по хосту адреса возврата,
роли пользователя на письмо не влияют. Приложение пакетных клубов
(app.lady-stretch.one, pack.base40.fit) получает письма Lady Stretch: светлые,
тёмная шапка #1a2027, розовый #f763fc, отправитель — `LADY_STRETCH_MAIL_FROM`. Типы писем: signup (код), magiclink
(код клиенту / ссылка сотруднику), recovery (ссылка), invite (ссылка),
email_change (код). Секреты живут только в Coolify у админки — у клиентского
приложения секретов нет по-прежнему.

## Важное о безопасности (уже исправлено в коде)

Раньше OTP в клиентском приложении был бутафорией: код не проверялся, а вход
шёл по выводимому из email паролю — войти можно было под любым клиентом, зная
только его почту. Теперь вход только по настоящему коду. После настройки
стоит просмотреть список пользователей (Supabase Studio → Authentication → Users) на предмет подозрительных аккаунтов,
созданных за время тестирования.
