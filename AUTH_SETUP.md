# Настройка почтовой авторизации (noreply@base40.fit)

Письма разделяются **по приложению, а не по человеку**. Админка и клиентское
приложение — разные сущности: один и тот же человек может быть и
администратором, и клиентом, и в клиентском приложении он должен идти
клиентским путём.

Отправку писем Supabase делегирует нашему серверу (Send Email Hook →
`https://admin.base40.fit/api/auth-email`), который смотрит, из какого
приложения пришёл запрос, и шлёт через **Resend** (`RESEND_API_KEY` у
club40-admin; с 2026-10-11 — единственный провайдер, Unisender Go убран):

- вход в **клиентское приложение** (app.base40.fit, pack.base40.fit) →
  клиентское письмо с **6-значным кодом** — даже если это администратор;
- вход в **админку** (admin.base40.fit) → письмо «Код для входа в
  админ-панель», тоже **6-значный код**.

Ссылок авто-входа нет ни в одном письме (решение владельца 2026-10-10).
Признак приложения — адрес возврата, который приложения передают явно; не
распознан — клиентское письмо.

Редактировать шаблоны в Supabase НЕ нужно — при включённом хуке они не
используются. Код обоих приложений готов; ниже — шаги настройки.

## Шаг 1. Resend

1. Домен `base40.fit` в Resend (resend.com → Domains) — **Verified** (DKIM и
   SPF в Cloudflare DNS). Только с подтверждённого домена письма уходят на
   любые адреса; с тестового `onboarding@resend.dev` — лишь на почту
   владельца аккаунта Resend.
2. API-ключ Resend (API Keys → Sending access).

Тариф (resend.com/pricing, 2026-10-11): **Free** — 3 000 писем/мес и не
больше **100 в день**, адресаты любые; **Pro** — $20/мес, 50 000 писем/мес
без дневного лимита. На тестах хватает Free, перед боевым запуском — Pro
(иначе после сотого кода за день письма перестанут уходить до следующих
суток; в логах club40-admin — ошибка Resend). Массовые рассылки клиентам —
отдельный тариф Resend (marketing), к кодам входа не относится.

## Шаг 2. Секрет хука в Supabase

Supabase self-hosted (Coolify, API `https://api.base40.fit`): Dashboard с
разделом Hooks нет, хук задаётся переменными сервиса **auth** (GoTrue).

1. Сгенерировать секрет: `echo "v1,whsec_$(openssl rand -base64 32)"`.
   (Если секрет уже стоит у club40-admin в `SEND_EMAIL_HOOK_SECRET` — взять его.)
2. **ПОКА НЕ включать** хук — сначала шаг 3.

## Шаг 3. Переменные в Coolify

Coolify → приложение **club40-admin** → Environment Variables, добавить две
runtime-переменные (галочку Build Variable НЕ ставить):

| Имя                      | Значение                          |
| ------------------------ | --------------------------------- |
| `SEND_EMAIL_HOOK_SECRET` | секрет из шага 2 (`v1,whsec_...`) |
| `RESEND_API_KEY`         | API-ключ из шага 1                |

Затем **Restart** приложения.

## Шаг 4. Включить хук

Coolify → ресурс Supabase → сервис **auth** → Environment, добавить:

```
GOTRUE_HOOK_SEND_EMAIL_ENABLED=true
GOTRUE_HOOK_SEND_EMAIL_URI=https://admin.base40.fit/api/auth-email
GOTRUE_HOOK_SEND_EMAIL_SECRETS=<секрет из шага 2, v1,whsec_...>
```

и перезапустить сервис auth. С хуком SMTP в Supabase не нужен.
Порядок важен: если включить хук до рестарта админки с переменными, письма
перестанут уходить вовсе (роут ответит 500).

## Шаг 5. Длина кода

Приложение рассчитано на 6 цифр. Проверьте `GOTRUE_MAILER_OTP_LENGTH`
(не задан = 6) и `GOTRUE_MAILER_OTP_EXP` (3600 сек достаточно).

## Шаг 6. Лимиты

`GOTRUE_RATE_LIMIT_EMAIL_SENT` у сервиса auth: поднять до разумного
(например, 100 в час) — с хуком отправка идёт через ваш Resend.

## Шаг 7. Проверка

1. Клиентское приложение, **почтой администратора** → «Получить код» →
   письмо от `Base40 <noreply@base40.fit>` с 6 цифрами и без ссылок →
   вход работает. Это главная проверка: администратор в клиентском
   приложении — клиент.
2. Регистрация нового email → письмо «Добро пожаловать» с кодом; после
   входа профиль создан, имя/телефон на месте.
3. Админка → почта сотрудника → письмо «Код для входа в админ-панель» с
   6 цифрами → вход.
4. Письма не в спаме.

Если письма перестали приходить: Coolify → club40-admin → Logs, искать
`[auth-email]` и `[mail]` (там текст ошибки Resend); Resend → Emails —
статус каждого письма. Откат — `GOTRUE_HOOK_SEND_EMAIL_ENABLED=false` (но без
настроенного SMTP встроенные письма Supabase уходить не будут).

## Как это устроено (для справки)

Роут `apps/admin/src/routes/api/auth-email.ts` проверяет подпись вебхука
(HMAC, standardized-webhooks); логика писем — `apps/admin/src/lib/auth-email.ts`,
покрыта тестами (`bun test`): решение принимается по хосту адреса возврата,
роли пользователя на письмо не влияют. Во всех типах писем (signup,
magiclink, recovery, invite, email_change) — код, без ссылок. Секреты живут только в Coolify у админки — у клиентского
приложения секретов нет по-прежнему.

## Важное о безопасности (уже исправлено в коде)

Раньше OTP в клиентском приложении был бутафорией: код не проверялся, а вход
шёл по выводимому из email паролю — войти можно было под любым клиентом, зная
только его почту. Теперь вход только по настоящему коду. После настройки
стоит просмотреть список пользователей (Supabase Studio → Authentication → Users) на предмет подозрительных аккаунтов,
созданных за время тестирования.
