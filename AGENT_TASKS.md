## Часть A. Изучить и посчитать (без покупок)

Источники: selectel.ru (облачные серверы, выделенные серверы, объектное
хранилище), калькулятор цен, docs.selectel.ru; reg.ru — почтовый хостинг
и DNS. Цены — **в рублях в месяц с НДС**.

1. **Облачный сервер 4 vCPU / 8 ГБ RAM / 80 ГБ SSD**, Ubuntu 24.04, —
   **самые дешёвые варианты** во всех линейках и регионах:
   - с долей процессора (shared-линейка; какая доля — 10/20/50 %) — для
     наполнения портала первые недели;
   - с **гарантированными 100 % vCPU** — для работы всех сотрудников;
   - для роста — те же линейки с 8 vCPU / 16 ГБ.
   Для каждого: тип диска и IOPS, скорость порта (нужно не меньше
   1 Гбит/с), сколько трафика наружу входит и цена сверх (ориентир 1–3 ТБ
   в месяц), цена публичного IP, почасовая ли оплата, **можно ли поменять
   конфигурацию (и линейку) без переустановки**, с тем же IP и диском, и
   сколько длится остановка.
2. **Самый дешёвый выделенный сервер** не меньше 4 ядер / 16 ГБ / SSD
   и 1 Гбит/с — цена, срок выдачи, есть ли RAID (для сравнения).
3. **Объектное хранилище S3** для бэкапов: цена за ГБ в месяц, за
   запросы и исходящий трафик; S3-адрес (endpoint) и path-style; бакет в
   **другом регионе**, чем сервер; ключи доступа к одному бакету
   (сервисный пользователь).
4. **Файрвол / группы безопасности** — бесплатны ли. Снимки диска сервера
   — цена (на случай, если дешевле S3, — для сравнения).
5. **Docker Hub:** есть ли у Selectel зеркало Docker Hub или рекомендация
   на случай, если Docker Hub из России недоступен (docs.selectel.ru, блог
   Selectel).
6. **Регистрация и оплата:** что нужно от основателя (документы юрлица),
   как быстро проверяют, оплата по счёту или картой, минимальный аванс.
7. **reg.ru, почтовый хостинг клиента:** какой тариф подключён к домену
   Lady Stretch, сколько ящиков свободно, **лимит отправки писем — в час и
   в сутки на ящик и на домен**, адрес и порты SMTP (465/587), можно ли
   отправлять от `noreply@<домен>` с внешнего сервера по SMTP с паролем,
   есть ли DKIM и как его включить. Ничего не меняй — только посмотри.
8. **reg.ru, DNS домена:** на каких DNS-серверах домен (reg.ru или
   другие), какие записи уже есть (A, MX, TXT — список, чтобы ничего не
   сломать), какие поддомены заняты.

## Часть 2. Внутри сервера — память, диск, падения (менять — только где написано)

Coolify https://coolify.base40.fit → **Servers** → сервер (localhost) →
**Terminal** (или значок терминала у сервера). Выполнить по одной команде и
скопировать вывод в отчёт (это только чтение, ничего не меняют):

```bash
uptime; nproc
free -h; swapon --show
df -h /
docker system df
docker stats --no-stream --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}" | sort -k3 -h | tail -25
docker ps --format "table {{.Names}}\t{{.Status}}" | head -40
dmesg -T 2>/dev/null | grep -iE "out of memory|oom-kill|killed process" | tail -20
journalctl -k --since "14 days ago" 2>/dev/null | grep -iE "oom|killed process" | tail -20
```

Оценка (впиши в отчёт цветом):

- `free -h`, колонка **available**: больше 3 GB — 🟢; 1,5–3 GB — 🟠; меньше
  1,5 GB — 🔴. Swap 0 B — отметить (при нехватке памяти ядро сразу убивает
  процессы, первым может пострадать Postgres).
- `df -h /`: занято меньше 70 % — 🟢; 70–85 % — 🟠; больше 85 % — 🔴 (при
  заполненном диске база останавливается).
- `uptime`, load average: меньше числа vCPU — 🟢.
- Любые строки про OOM / killed process за 14 дней — 🔴, переписать, какой
  процесс убит и когда.
- Контейнеры в статусе `Restarting` или с `Up` меньше часа (кроме только
  что задеплоенных) — записать.

Если диск 🔴: Coolify → сервер → **Docker Cleanup** (или Cleanup Storage) →
запустить очистку (удаляет неиспользуемые образы и кэш сборок; работающие
контейнеры и тома не трогает), затем снова `df -h /`.

Если swap **0 B**, а на диске свободно больше 20 GB — добавить файл подкачки
4 GB (страховка: при нехватке памяти, например во время сборки, ядро не
убьёт сразу базу). Команды по одной:

```bash
fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
grep -q '^/swapfile ' /etc/fstab || echo '/swapfile none swap sw 0 0' >> /etc/fstab
sysctl -w vm.swappiness=10 && echo 'vm.swappiness=10' > /etc/sysctl.d/99-swappiness.conf
swapon --show; free -h
```

Если любая команда выдала ошибку — остановиться, вывод в отчёт, дальше
этот шаг не продолжать (убрать подкачку: `swapoff /swapfile`).

## Часть 4. Supabase Auth — лимит писем с кодом (🔴 главный пункт)

Вход в приложения — только кодом из письма. У GoTrue есть **общий на весь
сервер** лимит писем в час (`GOTRUE_RATE_LIMIT_EMAIL_SENT`; по умолчанию
**30 в час**, раньше в инструкциях — 100). Он считает письма обоих
приложений и админки вместе. Утром, когда клиенты массово входят, при лимите
30–100 в час большинство получит ошибку «Слишком часто» вместо кода.

1. Coolify → ресурс **Supabase** → сервис **auth** (или общий список
   переменных ресурса) → Environment Variables. Записать значения (секретов
   в них нет): `GOTRUE_RATE_LIMIT_EMAIL_SENT`, `GOTRUE_RATE_LIMIT_HEADER`,
   `GOTRUE_RATE_LIMIT_OTP`, `GOTRUE_RATE_LIMIT_VERIFY`,
   `GOTRUE_RATE_LIMIT_TOKEN_REFRESH`, `GOTRUE_MAILER_AUTOCONFIRM`
   (`ENABLE_EMAIL_AUTOCONFIRM`), `GOTRUE_SMTP_MAX_FREQUENCY`,
   `GOTRUE_JWT_EXP` (`JWT_EXPIRY`), `GOTRUE_MAILER_OTP_EXP`,
   `GOTRUE_DISABLE_SIGNUP` (`DISABLE_SIGNUP` — должно быть `false`),
   `GOTRUE_HOOK_SEND_EMAIL_ENABLED`, `GOTRUE_HOOK_SEND_EMAIL_URI`. Не
   задана — так и писать «не задана».
2. Изменить:
   - `GOTRUE_RATE_LIMIT_EMAIL_SENT` = **`3000`** (писем в час на весь сервер:
     1000 клиентов с повторами и запасом; защиту от перебора это не
     ослабляет — у каждого адреса свой предел «раз в минуту»). Если
     переменной нет в списке — добавить её в сервис auth (в compose
     ресурса Supabase, блок `supabase-auth` → `environment`).
   - Только если `GOTRUE_RATE_LIMIT_HEADER` **задана** (например,

     трогать: по IP GoTrue тогда не ограничивает.
   - Больше ничего в auth не менять.
3. Применить: перезапустить **только сервис auth**, если Coolify это

# Задача 13. 🟠 Почта Lady Stretch: домен `lady-stretch.one` в Resend (2026-10-15)

Решение владельца 2026-10-15: клиенты пакетных клубов (приложение
https://app.lady-stretch.one и прежнее https://pack.base40.fit) получают
письма с кодом входа в брендинге Lady Stretch и **с отдельного адреса
`noreply@lady-stretch.one`**. Шаблон уже в коде админки (светлое письмо с
тёмной шапкой и белым логотипом Lady Stretch). Пока домен не подтверждён, письма
Lady Stretch уходят с прежнего `noreply@base40.fit` — вход не ломается.
Админка и app.base40.fit по-прежнему пишут от `Base40 <noreply@base40.fit>`.

Общие правила: ключи и пароли никуда не пересылать и не вставлять в отчёт;
домен `base40.fit` в Resend и его DNS-записи **не трогать**; существующие
DNS-записи `lady-stretch.one` (сайт, `app.`, почта на корне домена, если
есть) **не менять и не удалять** — только добавлять новые. **Если Resend
требует платный тариф — не покупать**, остановиться и написать владельцу
(на бесплатном сейчас до 3 доменов; если места нет — сообщить, какие домены
уже заняты).

**Проверка «сделано ли уже»:** resend.com → Domains → `lady-stretch.one` —
**Verified**, а у club40-admin в Coolify есть переменная
`LADY_STRETCH_MAIL_FROM` — переходи к Части 4.

### Часть 1. Resend — добавить домен

1. resend.com → **Domains** → посмотреть регион у `base40.fit` (например,
   Ireland `eu-west-1`) — запомнить.
2. **Add Domain** → `lady-stretch.one` (именно корневой домен, без `send.`
   и `app.`), Region — тот же, что у `base40.fit` → **Add**.
3. Resend покажет DNS-записи. Обычно это:
   - **MX** `send` → `feedback-smtp.<регион>.amazonses.com`, приоритет `10`;
   - **TXT** `send` → `v=spf1 include:amazonses.com ~all`;
   - **TXT** `resend._domainkey` → длинный ключ `p=MIIB...`;
   - (рекомендуется) **TXT** `_dmarc` → `v=DMARC1; p=none;`.

   Значения брать **ровно с экрана Resend** (копировать кнопкой), не из этой
   инструкции. Страницу с записями держать открытой.

4. В настройках домена (вкладка Configuration / Settings) выключить
   **Click tracking** и **Open tracking** — в письмах коды, ссылки не нужны.

### Часть 2. DNS у регистратора `lady-stretch.one`

DNS домена `lady-stretch.one` — у его регистратора (там же, где 2026-10-12
создавали A-запись `app.lady-stretch.one` → `62.238.104.251`), **не** в
Cloudflare base40.fit.

1. Открыть DNS-записи `lady-stretch.one`. Записать в отчёт, какие записи
   MX, TXT (SPF `v=spf1 …`) и `_dmarc` уже есть на корне домена (только
   имена и начало значений).
2. Добавить записи из Части 1, шаг 3, по одной:
   - имя — как у Resend (`send`, `resend._domainkey`, `_dmarc`). Если
     регистратор сам дописывает домен, вводить коротко (`send`); если
     требует полное имя — `send.lady-stretch.one`. Проверить, что в итоге
     не получилось `send.lady-stretch.one.lady-stretch.one`;
   - MX — приоритет `10`; TTL — по умолчанию (или 3600);
   - значение TXT вставлять целиком, без лишних пробелов; кавычки — только
     если регистратор их требует.
3. Если `_dmarc` на корне уже есть — второй **не создавать**, оставить
   существующий и написать об этом в отчёте.
4. MX и SPF на **корне** домена (если там настроена почта владельца) — не
   трогать: записи Resend живут на поддомене `send` и с ними не
   конфликтуют.

### Часть 3. Подтвердить домен и ключ

1. resend.com → Domains → `lady-stretch.one` → **Verify DNS Records**.
   Подождать (обычно 5–30 минут, бывает до нескольких часов), обновляя
   страницу. Нужен статус **Verified** у домена и у каждой записи (DKIM,
   SPF/MX). Если запись висит в Failed/Pending дольше часа — сверить имя и
   значение у регистратора с экраном Resend (частая ошибка — дважды
   дописанный домен в имени) и нажать Verify ещё раз.
2. **API Keys**: открыть ключ, который сейчас стоит у club40-admin (имя
   `club40-admin`). Если у него Permission **Full access** или Domain
   **All domains** — ничего не делать, перейти к Части 4. Если Domain —
   только `base40.fit` (так создавали в Задаче 11), с `lady-stretch.one` он
   отправлять не сможет — тогда:
   - **Create API Key**: имя `club40-admin-all`, Permission **Sending
     access**, Domain **All domains**; ключ (`re_...`) скопировать — он
     показывается один раз;
   - Coolify (https://coolify.base40.fit) → проект **club40** →
     **production** → **club40-admin** → Environment Variables →
     `RESEND_API_KEY` = новый ключ (runtime, галочку Build Variable НЕ
     ставить) → **Restart**;
   - проверка: https://admin.base40.fit → вход кодом — письмо «Код для
     входа в админ-панель Base40» пришло. **Только после этого** старый
     ключ `club40-admin` в Resend удалить (Revoke). Не пришло — вернуть
     старый ключ в Coolify, Restart, описать в отчёте.

### Часть 4. Coolify — включить отправку с нового адреса

**Только когда домен в Части 3 — Verified** (с неподтверждённого домена

1. Coolify → **club40-admin** → Environment Variables → добавить

2. **Restart** (или Redeploy, если Restart нет), дождаться статуса

3. https://admin.base40.fit/email/lady-stretch-logo-dark.png открывается —
   белый логотип Lady Stretch на тёмно-сером фоне (если 404 — значит, код ещё не

### Часть 5. Проверка

этой почтой в пакетном клубе) — взять тестового клиента из Задачи 11 или

1. https://app.lady-stretch.one (в браузере телефона или в режиме

   - отправитель — **Lady Stretch <noreply@lady-stretch.one>**;
   - тема — «Код для входа — Lady Stretch»;
   - светлое письмо: тёмная шапка с белым логотипом Lady Stretch, код из 6 цифр
     на бледно-розовой плашке;
   - во «Входящих», не в спаме.

   Код вводится, вход проходит.

2. В Gmail у этого письма: ⋮ → **Показать оригинал** → SPF, DKIM и DMARC —
   **PASS** (переписать в отчёт). Не PASS — вернуться к Части 2.
3. https://admin.base40.fit → вход кодом: письмо по-прежнему от
   `Base40 <noreply@base40.fit>`, оформление Base40 (жёлтое «40»).
4. resend.com → **Emails**: письма из шагов 1 и 3 — **Delivered**.
5. Если письмо из шага 1 не пришло: Coolify → club40-admin → **Logs**,
   строки `[mail]` / `[auth-email]` (например,
   `Resend 403: ... domain is not verified` или `... not authorized to send from lady-stretch.one` —

# Задача 2. Письма авторизации — доделать шаги 4–7

### Шаг 4. Хук включён?

Supabase Dashboard → **Authentication** → **Hooks** → **Send Email Hook**.

- Проверка: хук существует с URL `https://admin.base40.fit/api/auth-email`
  и переключатель стоит **Enabled**.
- Если Enabled уже стоит — иди к шагу 5.
- Если хук есть, но выключен — включи (Enable) и сохрани.
- Если хука нет вовсе (маловероятно) — создай: тип HTTPS, URL выше. ВНИМАНИЕ:
  при создании сгенерируется НОВЫЙ секрет — тогда его нужно скопировать и
  заменить значение `SEND_EMAIL_HOOK_SECRET` в Coolify (club40-admin →
  Environment Variables) и нажать Restart, и только потом включать хук.

### Шаг 5. Длина кода — МЕНЯТЬ НЕ НУЖНО

Supabase не позволяет настраивать Email OTP Length (всегда 6 цифр), и
клиентское приложение уже переведено на 6 ячеек. **Ничего не меняй.**
Можешь только проверить, что OTP Expiration = 3600 сек.

### Шаг 6. Проверка писем (выполни обязательно, даже если 4–5 были готовы)

1. Открой https://app.base40.fit → введи **почту владельца** → «Получить
   код». Должно прийти письмо от `Base40 <noreply@base40.fit>` с
   **6 цифрами и без единой ссылки**. Введи код — вход должен сработать.
2. Открой https://admin.base40.fit/auth → введи ту же почту → «Получить код
   для входа». Должно прийти **другое** письмо — «Код для входа в
   админ-панель», тоже **6 цифр и без единой ссылки**. Введи код на странице —
   откроется админка.
3. Ключевой критерий: **одна и та же почта в двух приложениях получает разные
   письма** (разная тема). Если в клиентском приложении пришло письмо
   админ-панели, в любом письме есть ссылка входа или письмо с адреса
   Supabase — остановись и сообщи владельцу.
4. Письма не в спаме.

Диагностика, если письма не приходят: Coolify → club40-admin → Logs, строки
`[auth-email]`. Аварийный откат: выключить хук в Supabase.

### Шаг 7. Лимиты

Supabase → **Authentication** → **Rate Limits**.

- Проверка: лимит отправки писем ≥ 30/час. Если уже поднят — готово.
- Если стоит маленький (2–4/час) — поставь 100/час.

# Задача 6. 🟢 Миграции под аналитику и новые фичи

Новые фичи (прочие продажи, оплата/скидки/возвраты, заморозка, гигиена данных).
Прогнать в SQL Editor **в этом порядке** (идемпотентно, проверено на локальном
Postgres 16). Требуют, чтобы `security_hardening.sql` был уже прогнан (нужен
`is_staff`).

1. `db/other_sales.sql` — каталог позиций `sale_items` + продажи `other_sales`.
2. `db/sales_payment.sql` — поля оплаты/скидок на `sales` и `other_sales` +
   таблица `refunds`.
3. `db/membership_freeze.sql` — заморозка (лимит в тарифе, статус `frozen`,
   журнал, RPC freeze/unfreeze). Переопределяет `activate_membership_from_sale`,
   поэтому запускать **после** `db/client_memberships_cancel.sql`.
4. `db/booking_hygiene.sql` — единый словарь статусов посещений, автоистечение
   `expire_memberships()`, триггер `last_visit_date`, причины/срок отмены брони.
5. `db/bookings_log_full_reason.sql` — добавляет причину и срок отмены во вью
   «Истории записей» (после 4).
6. `db/booking_waitlist.sql` — лист ожидания: запись в очередь при заполнении +
   счётчик `waitlist_count` (после 4; переопределяет функции записи/отмены).
7. `db/client_profile_backfill.sql` — карточки клиента для тех, кто
   зарегистрировался ДО автосоздания (триггер срабатывает только на нового
   пользователя), плюс функция самолечения `ensure_client_profile()`.
   **Запускать после 8.** Без неё уже зарегистрированные клиенты видят
   «Профиль клиента не привязан к студии» и не могут записаться.
8. `db/client_app_fixes.sql` — исправления по ревью клиентского приложения:
   регистрация создаёт карточку клиента, клиент может править свой профиль,
   матвью статистики закрыта, студия клиента синхронизируется с профилем.
   **Запускать после 7.**
9. `db/review_fixes.sql` — исправления по код-ревью: убрана двусмысленная
   перегрузка RPC, заморозка сама снимается по сроку, возвраты не блокируют
   удаление продажи, корректная ёмкость занятия, `frozen` в статусе клиента,
   простановка неявок ограничена студией. **Запускать последним.**

После прогона можно повесить на pg_cron ежедневно:
`select public.expire_memberships();` и (если уже прогнан stats) обновление
матвью статистики. Функциональность в админке (раздел «Прочие продажи» и пр.)
подтягивается кодом отдельно.
