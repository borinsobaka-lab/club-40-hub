# Задача 13. 🟠 Почта Lady Stretch: домен `lady-stretch.one` в Resend (2026-10-15)

Решение владельца 2026-10-15: клиенты пакетных клубов (приложение
https://app.lady-stretch.one и прежнее https://pack.base40.fit) получают
письма с кодом входа в брендинге Lady Stretch и **с отдельного адреса
`noreply@lady-stretch.one`**. Шаблон уже в коде админки (светлое письмо с
тёмной шапкой и белым логотипом Lady Stretch). Пока домен не подтверждён, письма
Lady Stretch уходят с прежнего `noreply@base40.fit` — вход не ломается.
Админка и app.base40.fit по-прежнему пишут от `Base40 <noreply@base40.fit>`.

Общие правила: ключи и пароли никуда не пересылать и не вставлять в отчёт;
домен `base40.fit` в Resend и его DNS-записи **не трогать**; существующие
DNS-записи `lady-stretch.one` (сайт, `app.`, почта на корне домена, если
есть) **не менять и не удалять** — только добавлять новые. **Если Resend
требует платный тариф — не покупать**, остановиться и написать владельцу
(на бесплатном сейчас до 3 доменов; если места нет — сообщить, какие домены
уже заняты).

**Проверка «сделано ли уже»:** resend.com → Domains → `lady-stretch.one` —
**Verified**, а у club40-admin в Coolify есть переменная
`LADY_STRETCH_MAIL_FROM` — переходи к Части 4.

### Часть 1. Resend — добавить домен

1. resend.com → **Domains** → посмотреть регион у `base40.fit` (например,
   Ireland `eu-west-1`) — запомнить.
2. **Add Domain** → `lady-stretch.one` (именно корневой домен, без `send.`
   и `app.`), Region — тот же, что у `base40.fit` → **Add**.
3. Resend покажет DNS-записи. Обычно это:
   - **MX** `send` → `feedback-smtp.<регион>.amazonses.com`, приоритет `10`;
   - **TXT** `send` → `v=spf1 include:amazonses.com ~all`;
   - **TXT** `resend._domainkey` → длинный ключ `p=MIIB...`;
   - (рекомендуется) **TXT** `_dmarc` → `v=DMARC1; p=none;`.

   Значения брать **ровно с экрана Resend** (копировать кнопкой), не из этой
   инструкции. Страницу с записями держать открытой.

4. В настройках домена (вкладка Configuration / Settings) выключить
   **Click tracking** и **Open tracking** — в письмах коды, ссылки не нужны.

### Часть 2. DNS у регистратора `lady-stretch.one`

DNS домена `lady-stretch.one` — у его регистратора (там же, где 2026-10-12
создавали A-запись `app.lady-stretch.one` → `62.238.104.251`), **не** в
Cloudflare base40.fit.

1. Открыть DNS-записи `lady-stretch.one`. Записать в отчёт, какие записи
   MX, TXT (SPF `v=spf1 …`) и `_dmarc` уже есть на корне домена (только
   имена и начало значений).
2. Добавить записи из Части 1, шаг 3, по одной:
   - имя — как у Resend (`send`, `resend._domainkey`, `_dmarc`). Если
     регистратор сам дописывает домен, вводить коротко (`send`); если
     требует полное имя — `send.lady-stretch.one`. Проверить, что в итоге
     не получилось `send.lady-stretch.one.lady-stretch.one`;
   - MX — приоритет `10`; TTL — по умолчанию (или 3600);
   - значение TXT вставлять целиком, без лишних пробелов; кавычки — только
     если регистратор их требует.
3. Если `_dmarc` на корне уже есть — второй **не создавать**, оставить
   существующий и написать об этом в отчёте.
4. MX и SPF на **корне** домена (если там настроена почта владельца) — не
   трогать: записи Resend живут на поддомене `send` и с ними не
   конфликтуют.

### Часть 3. Подтвердить домен и ключ

1. resend.com → Domains → `lady-stretch.one` → **Verify DNS Records**.
   Подождать (обычно 5–30 минут, бывает до нескольких часов), обновляя
   страницу. Нужен статус **Verified** у домена и у каждой записи (DKIM,
   SPF/MX). Если запись висит в Failed/Pending дольше часа — сверить имя и
   значение у регистратора с экраном Resend (частая ошибка — дважды
   дописанный домен в имени) и нажать Verify ещё раз.
2. **API Keys**: открыть ключ, который сейчас стоит у club40-admin (имя
   `club40-admin`). Если у него Permission **Full access** или Domain
   **All domains** — ничего не делать, перейти к Части 4. Если Domain —
   только `base40.fit` (так создавали в Задаче 11), с `lady-stretch.one` он
   отправлять не сможет — тогда:
   - **Create API Key**: имя `club40-admin-all`, Permission **Sending
     access**, Domain **All domains**; ключ (`re_...`) скопировать — он
     показывается один раз;
   - Coolify (https://coolify.base40.fit) → проект **club40** →
     **production** → **club40-admin** → Environment Variables →
     `RESEND_API_KEY` = новый ключ (runtime, галочку Build Variable НЕ
     ставить) → **Restart**;
   - проверка: https://admin.base40.fit → вход кодом — письмо «Код для
     входа в админ-панель Base40» пришло. **Только после этого** старый
     ключ `club40-admin` в Resend удалить (Revoke). Не пришло — вернуть
     старый ключ в Coolify, Restart, описать в отчёте.

### Часть 4. Coolify — включить отправку с нового адреса

**Только когда домен в Части 3 — Verified** (с неподтверждённого домена
Resend откажет, и клиенты останутся без кода).

1. Coolify → **club40-admin** → Environment Variables → добавить
   `LADY_STRETCH_MAIL_FROM` = `noreply@lady-stretch.one` (runtime, без
   Build Variable). Прочие переменные не трогать.
2. **Restart** (или Redeploy, если Restart нет), дождаться статуса
   Running/healthy.
3. https://admin.base40.fit/email/lady-stretch-logo-dark.png открывается —
   белый логотип Lady Stretch на тёмно-сером фоне (если 404 — значит, код ещё не
   выкачен: сообщить владельцу, переменную оставить).

### Часть 5. Проверка

Войти в клиентское приложение может только член клуба (карточка клиента с
этой почтой в пакетном клубе) — взять тестового клиента из Задачи 11 или
уточнить почту у владельца.

1. https://app.lady-stretch.one (в браузере телефона или в режиме
   эмуляции телефона) → почта тестового клиента → «Получить код». Письмо:
   - отправитель — **Lady Stretch <noreply@lady-stretch.one>**;
   - тема — «Код для входа — Lady Stretch»;
   - светлое письмо: тёмная шапка с белым логотипом Lady Stretch, код из 6 цифр
     на бледно-розовой плашке;
   - во «Входящих», не в спаме.

   Код вводится, вход проходит.

2. В Gmail у этого письма: ⋮ → **Показать оригинал** → SPF, DKIM и DMARC —
   **PASS** (переписать в отчёт). Не PASS — вернуться к Части 2.
3. https://admin.base40.fit → вход кодом: письмо по-прежнему от
   `Base40 <noreply@base40.fit>`, оформление Base40 (жёлтое «40»).
4. resend.com → **Emails**: письма из шагов 1 и 3 — **Delivered**.
5. Если письмо из шага 1 не пришло: Coolify → club40-admin → **Logs**,
   строки `[mail]` / `[auth-email]` (например,
   `Resend 403: ... domain is not verified` или `... not authorized to send from lady-stretch.one` —
   ключ без доступа к домену, Часть 3, шаг 2). Пока причина не найдена —
   **удалить** `LADY_STRETCH_MAIL_FROM` и сделать Restart: письма Lady
   Stretch снова пойдут с `noreply@base40.fit`, вход заработает.

### Отчёт владельцу

Регион и статус домена `lady-stretch.one` в Resend; какие DNS-записи
добавлены и какие уже были у регистратора; меняли ли API-ключ (только
имена ключей, не значения); заданные переменные Coolify (только имена);
результаты Части 5 (отправитель, тема, папка, SPF/DKIM/DMARC); понадобился
ли платный тариф.

# Задача 12. 🔴 Приложение пакетов переезжает на app.lady-stretch.one (2026-10-12)

установленные на телефоны иконки, его судьбу владелец решит позже.

**Проверка «сделано ли уже»:** https://app.lady-stretch.one открывается с
замком (действующий сертификат) и показывает розовый экран входа — Часть 1
сделана; в `GOTRUE_URI_ALLOW_LIST` есть `https://app.lady-stretch.one/**` —
Часть 2 сделана.

### Часть 1. Coolify — домен приложения

1. https://coolify.base40.fit → проект **club40** → **production** → ресурс

2. Поле **Domains**: записать в отчёт текущее значение, затем поставить

### Часть 2. Supabase Auth — разрешённый адрес

Без этого шага вход на новом адресе сломается: GoTrue заменит
незнакомый адрес на Site URL (= админка), и клиенту придёт письмо «вход в
админ-панель» вместо письма приложения.

1. Coolify → ресурс **Supabase** → сервис **auth** → переменные.
2. `GOTRUE_URI_ALLOW_LIST` (в шаблоне может называться
   `ADDITIONAL_REDIRECT_URLS`): записать в отчёт текущее значение (секретов в

   Существующие адреса (`https://app.base40.fit/**`,
   `https://pack.base40.fit/**`, админка) не удалять.
3. **Save** → перезапустить сервис auth (или весь Supabase, если по
   отдельности нельзя). Дождаться, что сервисы снова «Running».

### Часть 3. Проверка

1. https://app.lady-stretch.one → почта клиента, заведённого на портале в

# Задача 11. 🔴 Почта: переход с Unisender Go на Resend, вход в pack.base40.fit (2026-10-11)

Решение владельца 2026-10-11: письма с кодом входа (админка и оба клиентских
приложения — app.base40.fit и pack.base40.fit) отправляются **только через
Resend**. Unisender Go отключаем, всё, что в Unisender касается Base40, —
удаляем. Код уже переведён: админка шлёт письма только по `RESEND_API_KEY`,
`UNISENDER_GO_API_KEY` больше не читается.

Жалоба владельца: при входе в pack.base40.fit письмо с кодом не приходит.
Что Claude проверил снаружи (2026-10-11): GoTrue отвечает, вход по почте
включён, `disable_signup: false`; хук писем `https://admin.base40.fit/api/auth-email`
жив (на запрос без подписи — 401, то есть секрет и ключ почты у админки
заданы); в DNS `base40.fit` записи Resend есть (`resend._domainkey`, SPF и MX
на `send.base40.fit`), а **DKIM Unisender Go (`us._domainkey.base40.fit`) — нет**:
домен в Unisender Go подтверждён не полностью, и письма через него могли не
доставляться. Точную причину покажут логи (Часть 0).

Общие правила: ключи и пароли никуда не пересылать и не вставлять в отчёт;
кроме перечисленного ничего не удалять. **Если для нужного шага Resend
требует платный тариф — не покупать**, остановиться и написать владельцу,
какой тариф и почему.

**Проверка «сделано ли уже»:** у club40-admin нет переменной
`UNISENDER_GO_API_KEY`, а в resend.com → Emails есть письма «Код для входа —
Base40» за сегодня со статусом Delivered — переходи к Части 4.

### Часть 0. Диагностика (до изменений, только смотреть)

1. Coolify → **club40-admin** → **Logs**: найти строки `[auth-email]` и
   `[mail]` за последние сутки. Переписать в отчёт текст ошибок (без ключей),
   например `Unisender Go 200: ... (code ...)` или `Resend 403: ...`.
2. Coolify → club40-admin → **Environment Variables**: какие из
   `RESEND_API_KEY`, `UNISENDER_GO_API_KEY`, `SEND_EMAIL_HOOK_SECRET` заданы
   (только имена, без значений).
3. Coolify → ресурс **Supabase** → сервис **auth** → логи за сутки: строки с
   `hook`, `email`, `rate limit` (например `email rate limit exceeded`) — в
   отчёт.
4. Переменные сервиса auth (только проверить, значения секретов не
   выписывать): `GOTRUE_HOOK_SEND_EMAIL_ENABLED=true`,
   `GOTRUE_HOOK_SEND_EMAIL_URI=https://admin.base40.fit/api/auth-email`,
   `GOTRUE_URI_ALLOW_LIST` (или `ADDITIONAL_REDIRECT_URLS`) содержит
   `https://pack.base40.fit/**` и `https://app.base40.fit/**`,
   `GOTRUE_DISABLE_SIGNUP` (или `DISABLE_SIGNUP`) = `false` (**обязательно
   false**: клиент, заведённый на портале, при первом входе получает учётную
   запись автоматически, при `true` войти впервые нельзя),
   `GOTRUE_RATE_LIMIT_EMAIL_SENT` ≥ 100. Что не так — исправить в Части 2.

### Часть 1. Resend

1. resend.com → **Domains** → `base40.fit`: статус **Verified**. Если нет —
   открыть домен, сверить записи с Cloudflare DNS (Cloudflare → base40.fit →
   DNS), недостающие добавить ровно как показывает Resend, нажать
   **Verify** и дождаться Verified. В настройках домена выключить

# Задача 8. 🟠 Автоматические миграции БД в Coolify + второе клиентское приложение (2026-10-09)

Ты работаешь в браузере от имени владельца в панели Coolify:

- **Ничего не удаляй.** Не меняй другие переменные, домены и настройки,

- **Пароли и ключи никуда не пересылай и не пиши в отчёт** — ни в чат, ни в
  комментарии, ни в скриншоты (на скриншотах значения переменных скрывай).
- Порт базы 5432 **наружу не открывать** (никаких «Make it publicly
  available» / проброса портов у базы).
- Если какой-то шаг не получается или интерфейс выглядит не так, как описано, —
  остановись и опиши в отчёте, что видишь. Не импровизируй с настройками сети и
  базы.

Задача состоит из трёх частей. **Части 1 и 2 выполнены 2026-10-10; осталась
Часть 3** — после подтверждения владельцем адреса второго приложения.

---

### Часть 1. Подключение админки к базе — ✅ выполнена 2026-10-10

#### Шаг 1. Найти имя контейнера базы и пароль

1. Coolify → проект **club40** → **production** → ресурс **Supabase**.
2. В списке сервисов ресурса найди сервис базы — **supabase-db**. Запиши
   **полное имя его контейнера**: оно вида `supabase-db-<длинный id>` (видно в
   карточке сервиса / в его логах / в разделе с контейнерами). Нужен именно
   полный вариант с id, а не просто `supabase-db`.
3. Во вкладке **Environment Variables** ресурса Supabase найди значение
   `SERVICE_PASSWORD_POSTGRES` (в некоторых версиях оно же `POSTGRES_PASSWORD`).
   Это пароль базы — понадобится в Шаге 3. Никуда его не копируй, кроме
   переменной из Шага 3.

#### Шаг 2. Включить общую сеть у Supabase

По умолчанию Supabase живёт в своей изолированной сети, и админка его
контейнеры не видит.

1. В ресурсе **Supabase** → настройки (**Settings / General**) найди
   переключатель **Connect To Predefined Network**.
2. Если он **уже включён** — ничего не меняй, переходи к Шагу 3.
3. Если выключен — включи, сохрани и нажми **Restart** у ресурса Supabase.
   ⚠️ Во время перезапуска (обычно до пары минут) не работают вход в админку и
   клиентское приложение. Дождись, пока все сервисы Supabase снова будут
   **Running (healthy)**, и проверь, что https://admin.base40.fit/auth
   открывается.

#### Шаг 3. Добавить переменную DATABASE_URL в club40-admin

1. Coolify → **club40** → **production** → приложение **club40-admin** →
   **Environment Variables**.
2. Добавь переменную:
   - **Имя:** `DATABASE_URL`
   - **Значение:**
     `postgres://supabase_admin:<ПАРОЛЬ>@<ИМЯ_КОНТЕЙНЕРА>:5432/postgres`
     где `<ПАРОЛЬ>` — значение из Шага 1.3, `<ИМЯ_КОНТЕЙНЕРА>` — полное имя
     из Шага 1.2. Пример формы (не реальные значения):
     `postgres://supabase_admin:Ab12Cd34@supabase-db-k8s7f6d5:5432/postgres`
   - ⚠️ Если в пароле есть символы `@ : / ? # % &` — сообщи владельцу и не
     продолжай: такой пароль нужно отдельно закодировать.
   - Галочка **Build Variable — ВЫКЛЮЧЕНА** (только Runtime). Иначе пароль
     попадёт в собранный образ.
   - Если есть галочки **Is Literal** / **Multiline** — оставь по умолчанию.
3. Сохрани.
4. Нажми **Restart** у club40-admin (не Redeploy — пересборка не нужна), чтобы
   контейнер получил новую переменную. Дождись статуса **Running** и проверь,
   что https://admin.base40.fit/auth открывается.

#### Шаг 4. Проверить подключение изнутри админки

1. club40-admin → вкладка **Terminal** → подключись к контейнеру приложения.
2. Выполни команду (одной строкой, целиком):

   ```
   bun -e 'import { SQL } from "bun"; const db = new SQL(process.env.DATABASE_URL); const [r] = await db`select current_user as "user", (select rolsuper from pg_roles where rolname = current_user) as superuser, to_regclass(${"public.studios"})::text as studios`; console.log(r); await db.close();'
   ```

3. **Ожидаемый результат:**

   ```
   { user: "supabase_admin", superuser: true, studios: "studios" }
   ```

4. Если вывод другой:
   - `Failed to connect` / `getaddrinfo` / `ENOTFOUND` — неверное имя
     контейнера или не сработал Шаг 2. Проверь имя (полное, с id) и что
     Supabase перезапущен с включённой общей сетью.
   - `password authentication failed` — неверный пароль в `DATABASE_URL`.
   - `superuser: false` — запиши это в отчёт, дальше не продолжай.
   - `DATABASE_URL` не определён (ошибка про `undefined`) — переменная не
     применилась: проверь Шаг 3 и сделай Restart ещё раз.
