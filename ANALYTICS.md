# Аналитика — отчёты сети

Статус: **первая версия сделана 2026-10-26** (раздел рейки «Аналитика»).
Схема — `db/migrations/2026-10-26_zz_analytics.sql`, тесты базы —
`db/analytics.test.ts`, код админки — `apps/admin/src/lib/analytics/`
(расчёты + тест), `components/analytics/`, `routes/_authenticated/analytics/`.

## Зачем

Lady Stretch параллельно делала свой портал аналитики
(analytics.lady-stretching.ru: Python + SQLite на VPS Selectel, свои
пользователи и права). С переходом сети на наш портал он не нужен: решение
владельца 2026-10-26 — сделать у нас раздел «Аналитика» с теми же
инструментами, но в нашей архитектуре (Postgres, RLS, роли «Пользователей и
ролей») и нашей дизайн-системе.

## Что было у Lady Stretch (по их документации, архив владельца 2026-10-26)

1. **Аналитика 1С** (выгрузки 1С в Excel → локальная программа обработки →
   снимок SQLite с дневными агрегатами → загрузка на портал):
   - **Выручка** — города → студии, текущий месяц по календарным неделям
     (пн–вс, обрезаны месяцем), факт, прогноз (факт / прошедшие дни × дней в
     месяце), полгода истории, фильтр «открытые / закрытые», поиск,
     «точка 0» (месячная цель города);
   - **Продажи абонементов** — продажи, новые / повторные, оплаты новых и
     повторных, средние чеки, динамика к тем же датам прошлого месяца и
     прошлого года, графики за 9 месяцев, номенклатуры;
   - **Занятия и посещаемость** — занятия, записи, посещения, средние на
     занятии, доходимость, сравнения, направления;
   - **Воронка пробного** — записи → посещения → покупка в день пробного →
     покупка в пределах 14 дней, виды пробных;
   - **Нулевая номенклатура** — продажи с нулевой стоимостью (кроме
     пробных): город → студия → номенклатура;
   - **«Мой город»** — единый отчёт партнёра по своим городам: выручка,
     прогноз, точка 0, продажи по сегментам, «что покупают» (все / новые /
     продления), направления, пробные, таблица студий;
   - **Топ-10 городов** за месяц — покупка в день пробного, за 14 дней,
     продления без возвращённых, возвращённые.
2. **FitBase** — те же отчёты (выручка, продажи, посещаемость, воронка,
   «Мой город · FitBase») для студий на FitBase: ночная загрузка по API,
   своя SQLite.
3. **Маркетинг** — amoCRM (лиды из воронок новых лидов, квалификация по
   «Основанию для закрытия», записались / пришли / купили, когорта по
   месяцу создания сделки, срез на 1-е число и «догрев»), VK Ads (расходы
   кабинетов, ЛФ / СС, остатки бюджета, уведомления партнёрам), «Реестр
   таргета» по городам (расход, заявки, цена заявки, планы), Авито
   (кабинеты, кампании, заявки по UTM из amoCRM).
4. **Портал** — admin / viewer, партнёр = viewer с городами, журнал
   действий, онлайн и время в отчётах, read-only API агрегатов для Custom GPT.
5. **Inbox VK** (сообщения сообществ) — отдельный сервис, к аналитике не
   относится.

(если есть закрытые клубы).

### Правила расчёта (как у Lady Stretch, на наших данных)

- **Выручка** — поступившие деньги: продажа абонемента без графика — вся
  сумма в день продажи, рассрочка — внесённые платежи в день внесения,
  прочие продажи — в день продажи, возвраты вычитаются в день возврата.
  То же, что «Фактическая выручка» дашборда и зарплаты. Даты — по Тбилиси.
- **Прогноз** — выручка за прошедшие полные дни (до вчера) / их число × дней
  в месяце; только для текущего месяца, 1-го числа — «—». Прогноз города и
  сети — от их суммы, не сумма прогнозов клубов.
- **Точка 0** — у клуба в «Настройках»; у города — сумма точек 0 открытых
  клубов, если она задана у всех.
- **Новый / продление / возврат** — как `classifySales` дашборда: до
  продажи абонементов не было — новый; прежний действовал или закончился не
  раньше чем за 14 дней — продление; перерыв дольше — возврат. Пробные и
  разовые — свои виды, историей не считаются; пакет персональных — своя
  история. «Повторные» Lady Stretch = продления + возвраты.
- **Средний чек** — поступившее минус возвраты / число продаж, по которым в
  периоде поступили деньги (как у Lady Stretch: не делить на созданные
  продажи).
- **Занятия** — уже начавшиеся и не отменённые клубом групповые; записались
  — «Записан» + «Посетил» + «Не пришёл»; пришли — «Посетил»; доходимость —
  пришли / записались.
- **Пробное** — продажа номенклатуры «Пробное» (`memberships.kind =
trial`); дата пробного — первое посещение по нему (без посещения — дата
  продажи); купил — абонемент или пакет персональных того же клиента с
  суммой > 0, проданный в день пробного или в следующие 13 дней. Конверсии
  — от пришедших.
- Итоговые доли и средние — из итоговых числителя и знаменателя; нет
  знаменателя — «—», а не 0. Изменение к прошлому периоду — относительное, %;
  нет базы — «нет базы».

### Доступ

- **Раздел клуба «Аналитика»** (`club.analytics` в каталоге прав): в каких
  клубах человек видит отчёты. «Владелец клуба» и «Управляющий» (все
  разделы) — свои клубы (= «Мой город» партнёра); «Куратор клубов» —
  закреплённые (право добавлено в стартовую роль); сотрудник УК — роль с
  «Аналитикой» во всех клубах или клубах бренда. Ресепшн («Администратор
  клуба») и тренеры отчётов не видят, пока им не отметят раздел.
- **Сетевое право «Аналитика: точка 0 и статус клубов»** (`analytics.manage`)
  — страница «Настройки». У людей вне модели прав — владелец клуба.
- Граница — база: RPC `analytics_*` (security definer) считают только клубы
  `auth_analytics_studio_ids()` (роль в клубе + раздел открыт; запрошенный
  чужой клуб молча отбрасывается) и отдают только агрегаты — без клиентов,
  телефонов, имён. Внутренние функции (`analytics_ids`,
  `analytics_sale_origins`) снаружи не вызываются.

### Устройство

- База: `analytics_scope` (клубы, город, бренд, точка 0, закрытие, право
  правки), `analytics_revenue` / `analytics_sales` / `analytics_classes` /
  `analytics_trials` (корзина день или месяц), `analytics_zero`,
  `analytics_settings_save`; таблица `analytics_studio_settings`. Строки
  отдаются массивами в jsonb — без лимита PostgREST в 1000 строк.
- Админка: запросы — `lib/analytics/data.ts` (ключи `["analytics", …]`),
  расчёты — `lib/analytics/logic.ts` (+ тест: города, недели, сдвиг
  периода, прогноз, точка 0, продажи, занятия, пробные, рейтинг, нулевые),
  подписи — `lib/analytics/labels.ts` (их же берут скелетоны), каркас и
  фильтры — `components/analytics/analytics-shell.tsx` +
  `hooks/use-analytics-filters.ts`.

## Что дальше (не вошло)

1. **Данные клубов на 1С и FitBase.** Сейчас отчёты считают нашу базу:
   продажи, платежи, расписание. Клубы сети, которые ещё ведут учёт в 1С
   или FitBase, появятся, когда будет источник:
   - перенос в нашу CRM (как перенос клиентов из 1С 2026-10-18) — отчёты
     заработают сами;
   - или загрузка агрегатов: таблицы `analytics_ext_*` (клуб × день:
     выручка, продажи по видам и номенклатурам, занятия, пробные) с
     `source = '1c' | 'fitbase'`; каждая RPC добавляет их через `union all`
     в свою выборку фактов. Для 1С — загрузка снимка, который уже готовит их
     программа обработки (дневные агрегаты), для FitBase — ночная загрузка
     по API (endpoints и правила — в их `CALCULATIONS.md`). Нужны решение
     владельца и ключи.
2. **Маркетинг**: amoCRM (у нас уже есть подключение amoCRM — «Очередь
   ответственных»), VK Ads, Авито, «Реестр таргета», планы таргета и
   уведомления партнёрам о бюджете. Нужны токены кабинетов и решение, какие
   отчёты переносить первыми.
3. **Точка 0 по месяцам** (сейчас одна сумма на клуб) и история статуса
   клуба (сейчас — текущий: закрытый клуб закрыт во всех месяцах отчёта).
4. **Валюта по клубу**: суммы показываются в лари (как во всей админке);
   для клубов в России нужна валюта у клуба.
5. **Часовой пояс клуба**: даты считаются по Тбилиси.
6. **Read-only API для Custom GPT** и журнал просмотров отчётов — по
   запросу владельца.
