# Запись на массаж NEBA в приложении Lady Stretch

Задание и справочник для разработчика клиентского приложения (`apps/client`,
пакетная сборка https://app.lady-stretch.one). Подготовлено 2026-10-15.

## Коротко

- Массажный кабинет **NEBA** записывает клиентов в своей системе записи
  (репозиторий `borinsobaka-lab/booking-system`: витрина
  https://booking.neba.space, админка https://booking.neba.space/#/admin-panel).
  Задача — встроить **ту же запись** в раздел массажа приложения: клиентка
  выбирает мастера, услугу, дату и время прямо в приложении, запись попадает в
  систему NEBA, письма уходят те же, что с витрины.
- Приложение — **только экраны поверх API NEBA**. Таблиц и миграций в
  Supabase, серверных функций, новых переменных в Coolify — не нужно. Всё
  остальное делает сервер NEBA: проверяет, свободно ли время (с учётом общего
  кабинета и запаса до сеанса), сохраняет запись, шлёт письма и напоминания,
  списывает абонемент NEBA.
- Для приложения на сервере NEBA сделано (ветка `claude/kind-curie-w0xxhu`
  репозитория `booking-system`): запросы с app.lady-stretch.one разрешены
  (CORS), сервер сам отдаёт свободное время (`GET /api/slots`), запись
  помечается «из приложения Lady Stretch» (`source`), в ответе на запись —
  токен отмены.
- **Перед началом проверить, что сервер NEBA обновлён:**

  ```bash
  curl -s -o /dev/null -w '%{http_code}\n' https://booking-system.borin-sobaka.workers.dev/api/slots
  curl -sI -H 'Origin: https://app.lady-stretch.one' \
    https://booking-system.borin-sobaka.workers.dev/api/public | grep -i access-control-allow-origin
  ```

  Нужно `200` и `access-control-allow-origin: https://app.lady-stretch.one`.
  Иначе (404 / другой адрес) — сервер ещё не обновлён: ветку `booking-system`
  надо смержить и задеплоить Worker (это делает владелец), до этого браузер
  приложения запросы к NEBA не пропустит. Разрабатывать можно на локальном
  моке (раздел 7).

## 1. Как это работает

```
Приложение (браузер клиентки) ──HTTPS──▶ API NEBA (Cloudflare Worker) ──▶ данные NEBA
   GET  /api/public    каталог: студия, услуги, мастера, отзывы
   GET  /api/slots     свободное время (считает сервер)
   POST /api/bookings  запись → письма
```

Что происходит после `POST /api/bookings`:

1. Сервер ещё раз проверяет время. Пока клиентка заполняла форму, его могли
   занять — тогда ответ `409`, запись не создаётся.
2. Запись сохраняется: видна в админке NEBA в «Записях» (в карточке —
   «Откуда: Приложение Lady Stretch»), уведомление владельцу —
   «Новая запись (приложение Lady Stretch): Ана → Виктория · 16 октября, 10:00 ·
   классика».
3. Письма (на английском, как с витрины): клиентке — «Booking confirmed — NEBA»
   (услуга, мастер, дата и время, цена, адрес, телефон и WhatsApp студии,
   кнопка «Cancel booking» — ведёт на booking.neba.space); сотрудникам NEBA —
   «New booking»; мастеру — «New booking for you».
4. За час до сеанса — напоминание клиентке; через ~10 минут после сеанса —
   просьба оценить мастера (отзыв появится у мастера в каталоге).
5. Абонемент NEBA привязан к **номеру телефона**: если он есть, запись сама
   идёт «по абонементу» (в ответе `booking.membership: true`, на месте
   клиентка не платит). Поэтому телефон — в международном виде, как в карточке
   клиента: «+995 555 12 34 56».
6. Отмена — кнопкой из письма, из админки NEBA или из приложения (токен,
   раздел 2.4): письма об отмене клиентке, сотрудникам и мастеру, время
   освобождается.

## 2. API NEBA

Адрес: **`https://booking-system.borin-sobaka.workers.dev`** (он же зашит в
витрину NEBA, публичный). Из браузера доступен только с
`https://booking.neba.space` и `https://app.lady-stretch.one`; `localhost` —
нет (для разработки — мок, раздел 7). Все ответы — JSON; ошибка —
`{ "error": "текст по-русски" }` и код 400/403/404/409/500. Всё время — по
часам Тбилиси (UTC+4, без перехода на летнее время), даты — `YYYY-MM-DD`,
время — `HH:MM`.

### 2.1 `GET /api/public` — каталог

```jsonc
{
  "brand": { "name": {"en":"NEBA","ka":"NEBA","ru":"NEBA"},
             "address": {"en":"125, Shalva Nutsubidze, Tbilisi", …},
             "avatar": "data:image/…", "banner": null },
  "settings": { "minLeadMinutes": 120, "rooms": 1, "phone": "…", "whatsapp": "…" },
  "services": [ { "id": "…", "name": {"en","ka","ru"}, "description": {…},
                  "durationMin": 60, "price": 79, "image": "data:image/…" | null } ],
  "specialists": [ { "id": "…", "firstName": {…}, "lastName": {…}, "role": {…},
                     "bio": {…} /* HTML */, "avatar": "data:image/…" | null,
                     "serviceIds": ["…"], "inactive": true /* только у неактивных */ } ],
  "reviews": [ { "id","specialistId","authorName","rating" /*1–5*/,"text","date","avatar" } ],
  "schedules": […], "busy": […]   // приложению не нужны — есть /api/slots
}
```

- Тексты — `{en, ka, ru}` (у старых записей — строка): брать язык клиента →
  английский → русский → грузинский (`pickLoc` в модуле, раздел 5).
- Порядок услуг и мастеров в массивах — порядок, который задал владелец NEBA;
  так и показывать. Неактивные мастера (`inactive: true`) — в конце списка,
  выбрать нельзя.
- `bio` мастера — HTML из простого редактора NEBA (теги `p`, `div`, `br`,
  `strong`, `b`, `ul`, `li`). В приложении HTML не вставляют
  (`src/lib/formatted-text.tsx` — всё рисует React): разобрать `DOMParser` и
  отрисовать эти теги React-элементами, остальное — текстом. Описание услуги
  (`description`) — обычный текст с переносами строк.
- Картинки — `data:`-URL прямо в JSON, поэтому ответ большой (~550 КБ).
  Грузить один раз и держать в кэше (`staleTime` 10 минут), **не сохранять**
  в localStorage (`meta: { persist: false }` — см. `src/lib/query-persist.ts`).
- Цена — лари: `79 ₾` (`Intl.NumberFormat` + « ₾»).

### 2.2 `GET /api/slots` — свободное время

Параметры: `days` (1–92, по умолчанию 31), `from` (`YYYY-MM-DD`, не раньше
сегодня; по умолчанию сегодня). Приложению хватит `?days=62`.

```jsonc
{
  "today": "2026-10-15",          // сегодня по часам студии
  "from": "2026-10-15",
  "to": "2026-12-15",
  "step": 30,
  "slots": {
    "<specialistId>": {
      "<serviceId>": {
        "2026-10-16": ["10:00", "10:30", "11:00", …],
        "2026-10-18": [ … ]
      }
    }
  }
}
```

- Здесь только то время, на которое **сейчас можно записаться онлайн**: внутри
  рабочих окон мастера, мимо перерывов и записей, при свободном общем кабинете,
  в будущем и не ближе `minLeadMinutes` (сейчас 2 часа) до начала. Это та же
  проверка, что сервер делает при записи. Сетка — от начала рабочего окна шагом
  30 минут, сеанс целиком помещается в окно.
- Неактивных мастеров и дней без свободного времени в ответе нет.
- Ничего не пересчитывать на телефоне: все вопросы экранов («есть ли время в
  этот день», «свободен ли мастер в 12:00», «ближайшее время мастера») —
  поиск по этой карте (функции модуля, раздел 5).
- «Прошедшие дни» в календаре считать от `today` из ответа, не от часов
  телефона (у туристки телефон может жить в другом поясе).
- Обновлять: при входе в раздел, при открытии шага «Дата и время», если данным
  больше минуты, после каждой записи и после ответа `409`.

### 2.3 `POST /api/bookings` — записаться

```jsonc
{
  "specialistId": "…",
  "serviceId": "…",
  "date": "2026-10-16",
  "start": "10:00", // время из /api/slots
  "clientName": "Ана Кикнадзе", // обязательно
  "clientPhone": "+995 555 12 34 56", // обязательно, международный вид
  "clientEmail": "ana@example.com", // в приложении обязательно (письма)
  "comment": "…", // необязательно, до 1000 символов
  "consent": true, // галочка согласия — иначе 400
  "lang": "ru", // en | ka | ru — язык клиентки
  "source": "lady-stretch-app", // метка «из приложения» (модуль ставит сам)
}
```

Ответ `200`:

```jsonc
{
  "ok": true,
  "booking": { "id": "mv9s…", "specialistId": "…", "serviceId": "…",
               "date": "2026-10-16", "start": "10:00", "end": "11:00",
               "status": "confirmed", "membership": true /* если по абонементу */, … },
  "cancelToken": "…"   // для отмены из приложения (раздел 2.4)
}
```

Ошибки (текст `error` — по-русски для админки; клиентке показывать свой
перевод по коду и смыслу):

| Код                | `error`                                                                                       | Что показать и сделать                                                                                                    |
| ------------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 409                | `Это время уже занято`                                                                        | «Это время только что заняли — выберите другое»; обновить слоты, вернуть на шаг «Дата и время» (мастер и услуга остаются) |
| 409                | `Онлайн-запись на это время уже закрыта — выберите время попозже`                             | то же, другим текстом                                                                                                     |
| 409                | `Мастер больше не принимает записи`                                                           | «Мастер больше не принимает записи»; обновить каталог, вернуть к выбору мастера                                           |
| 409                | `Услуга не найдена`                                                                           | обновить каталог, начать заново                                                                                           |
| 400                | `Укажите имя и телефон` / `Требуется согласие на обработку данных` / `Неверные данные записи` | ошибка формы — до сервера не должно доходить                                                                              |
| 0 (нет сети) / 5xx | —                                                                                             | «Не удалось создать запись. Попробуйте ещё раз»                                                                           |

### 2.4 Своя запись: `GET /api/bookings/lookup`, `POST /api/bookings/cancel-public`

Нужны, только если в приложении будет «Мои записи на массаж» с отменой
(раздел 3.7). Ключ — `id` записи и `cancelToken` из ответа на запись (тот же
токен, что в ссылке «Cancel booking» из письма).

- `GET /api/bookings/lookup?id=…&token=…` →
  `{ booking: {id,date,start,end} | null, service, master, address, phone, whatsapp, brand }`;
  `booking: null` — запись уже отменена (кем угодно). Неверный токен — `403`.
- `POST /api/bookings/cancel-public` с `{ id, token }` → `{ ok: true }`
  (уже отменена — `{ ok: true, already: true }`). Письма об отмене уйдут
  автоматически.

## 3. Экраны — шаг за шагом (как на booking.neba.space)

Порядок шагов, состав и поведение — как на витрине NEBA (её стоит открыть на
телефоне и пройти). Внешний вид — в стиле приложения (фирменный цвет,
шрифты, компоненты shadcn), не в сером стиле NEBA.

### 3.0 Начало раздела

- Подзаголовок: «Онлайн-запись за минуту. С чего начнём?»
- Три большие кнопки во всю ширину (слева иконка в круге, справа название
  жирным и серая подпись):

  | Кнопка               | Подпись                                  | Путь (шаги)                                    |
  | -------------------- | ---------------------------------------- | ---------------------------------------------- |
  | 👤 **Мастер**        | Выбрать мастера, потом услугу и время    | Мастер → Услуга → Дата и время → Подтверждение |
  | 📅 **Выбрать дату**  | Свободные дата и время → услуга → мастер | Дата и время → Услуга → Мастер → Подтверждение |
  | ☰ **Выбрать услугу** | Услуга → мастер → дата и время           | Услуга → Мастер → Дата и время → Подтверждение |

- Пока грузится каталог — скелетоны / «Загрузка…». Нет услуг или ни одного
  активного мастера — «Салон ещё настраивается. Загляните чуть позже.»
- Плашка NEBA (по желанию владельца): логотип `brand.avatar`, название
  `brand.name`, адрес `brand.address`.

### 3.1 Каркас записи (общий для всех шагов)

- **Шапка, закреплена при прокрутке:** маленькая плашка NEBA (логотип 40 px,
  название, адрес; нажатие — в начало раздела); строка: кнопка «‹ Назад»,
  полоска прогресса (заполнена на номер шага / 4), счётчик «1/4».
- Заголовок шага (у «Даты и времени» — меняется, см. 3.4).
- **Низ, закреплён:** основная кнопка во всю ширину «Продолжить» — появляется,
  только когда на шаге что-то выбрано. Выбор сам по себе дальше не переводит
  (защита от случайного нажатия), кроме кнопок времени на карточке мастера.
- При переходе между шагами — прокрутка наверх.
- **Переход вперёд:** после выбора открывается первый по порядку пути шаг, на
  котором ещё ничего не выбрано; если выбрано всё — «Подтверждение». Поэтому
  время, выбранное на карточке мастера, пропускает шаг «Дата и время».
- **«Назад»:** на первом шаге — выход в начало раздела; иначе — предыдущий
  шаг, и выбор этого предыдущего шага и всех следующих сбрасывается (путь
  «Мастер», шаг 3 → «Назад» → шаг 2, услуга, дата и время сброшены).

### 3.2 Шаг «Выберите мастера»

Кого показывать:

- путь «Мастер» — всех (`allSpecialists`);
- путь «Выбрать услугу» — делающих услугу (`specialistsDoing`);
- путь «Выбрать дату» (дата и время уже выбраны) — делающих услугу; свободен
  только тот, у кого `specialistFreeAt(...)`; остальные — серые, с пометкой
  «занят в это время», выбрать нельзя.
- Неактивные — в конце, приглушены, пометка «не принимает записи», без
  галочки — только «i».

Строка мастера: аватар 56 px (круг; нет фото — первая буква имени), имя
(`firstName lastName`), роль (например «Массажист»), строка рейтинга — 5
звёзд по среднему (дробные — частично закрашены) и «3 отзыва» / «Нет
отзывов» (`ratingOf`). Справа — круглая кнопка «i» (карточка мастера) и
круглая галочка 28 px (✓, когда выбран). Нажатие на строку или галочку
отмечает / снимает выбор (выбран всегда один) → внизу «Продолжить».

**Ближайшее время** — под строкой каждого свободного мастера, только если
время ещё не выбрано (пути «Мастер» и «Выбрать услугу»): разделитель, текст
«Ближайшее время для записи **пт, 16 окт**:» и кнопки-«таблетки» с первыми 5
временами этого дня + таблетка «другое время» (`nearestSlots`; в пути
«Мастер» — по самой длинной услуге мастера, тогда время подойдёт под любую).

- Таблетка со временем → выбраны мастер, дата и время сразу → следующий
  невыбранный шаг (путь «Мастер» — «Услуга», путь «Выбрать услугу» —
  «Подтверждение»).
- «другое время» → выбран мастер, сразу шаг «Дата и время».
- Нет свободного времени в ближайшие 62 дня — блока нет.

**Карточка мастера** («i»; на витрине заменяет список, в приложении можно
шторкой): аватар 96 px, имя, роль, пометка «не принимает записи» у
неактивного, строка рейтинга по центру, биография (`bio`, см. 2.1), «Отзывы» — новые
сверху: аватар 40 px (или первая буква), имя автора жирным, дата «Пятница, 16
октября», звёзды, текст. Кнопки внизу: «Выбрать этого специалиста» (основная;
нет у неактивного; недоступна, если мастер занят в выбранное время) и
«Закрыть биографию».

Пусто: «Пока нет мастеров для этой услуги.»

> В приложении у массажистов уже есть вкладка «Массажисты» в «Студии»
> (Supabase, `trainers.role = 'masseur'`, свои оценки). В записи мастера и
> отзывы — **из NEBA** (`/api/public`), id у них свои, связи между ними нет.
> Кнопку «Записаться к этому массажисту» из вкладки «Массажисты» без
> сопоставления (например, поле с id мастера NEBA у сотрудника) не сделать —
> решает владелец.

### 3.3 Шаг «Выберите услугу»

Какие услуги:

- выбран мастер — его услуги (`servicesOf`);
- выбраны дата и время (путь «Выбрать дату») — те, на которые в это время есть
  свободный мастер (`servicesBookableAt`);
- иначе — все.

Карточка во всю ширину: широкая картинка 21:8 (cover; нет картинки — заглушка
💆), круглая галочка в правом верхнем углу; название и цена в одной строке
(цена справа, «79 ₾»), длительность «⏱ 1 ч» («45 мин», «1 ч 30 мин»);
описание — 2 строки и ссылка «Развернуть» / «Свернуть» (она выбор не
переключает). Нажатие на карточку отмечает / снимает выбор → внизу
«Продолжить».

Пусто: «Нет доступных услуг для этого выбора.»

### 3.4 Шаг «Дата и время»

- Заголовок: «Выберите дату», после выбора дня — «Выберите время».
- **Календарь месяца:** «Октябрь 2026» со стрелками ‹ ›; дни недели Пн…Вс
  (неделя с понедельника); клетки ~38 px со скруглением. Состояния:
  - прошедший день (раньше `today`) или день без времени — серый, неактивный;
  - есть время (`dayAvailable` с текущим выбором) — белый, с рамкой, цифра
    жирная, нажимается;
  - сегодня — рамка фирменного цвета;
  - выбранный — залит фирменным цветом, цифра белая.
- Открывается текущий месяц; листать — в пределах загруженных слотов (не
  раньше месяца `today`, не дальше месяца `to`).
- После выбора дня — ниже серым полная дата «Пятница, 16 октября» и сетка
  кнопок времени (`startsFor`; ширина кнопки от ~84 px, скругление 12 px,
  жирный текст; выбранная — залита фирменным цветом). Нет времени — «На этот
  день нет свободного времени.» Смена дня сбрасывает время.
- Выбраны день и время → внизу «Продолжить».

### 3.5 Шаг «Подтверждение»

- **Сводка:** по центру мастер (аватар 72 px, имя, роль); карточка: «Дата и
  время» — «Пятница, 16 октября, 10:00–11:00» (конец = начало +
  `durationMin`), «Услуга» — название, линия, «Итого к оплате» — «79 ₾»
  жирным.
- **«Ваши данные»:**
  - «Имя \*» (плейсхолдер «Введите имя») — подставить из карточки клиента
    (`clientCardQuery`: `full_name` или имя + фамилия);
  - «Номер телефона \*» — поле с кодом страны и маской (по умолчанию Грузия
    +995, «XXX XX XX XX»); в приложении уже есть такое поле
    (`components/ui/phone-input.tsx`, правила — `src/lib/phone.ts`);
    подставить `clients.phone`; номер должен быть полным; отправлять в
    международном виде «+995 555 12 34 56»;
  - «Email \*» (плейсхолдер «Введите email») — подставить почту учётной
    записи; проверка `^[^\s@]+@[^\s@]+\.[^\s@]+$`, ошибка под полем —
    «Проверьте адрес почты»; обязателен (на него подтверждение и
    напоминание);
  - «Комментарий» — многострочное, 3 строки, «Пожелания к записи
    (необязательно)».
- **Согласие** (галочка, каждый раз снята): «Я согласен(а) на обработку моих
  персональных данных, в том числе специальных категорий, для оформления
  записи в соответствии с [политикой обработки
  данных](https://neba.space/privacy).» Ссылка открывается в новой вкладке,
  нажатие на неё галочку не переключает. Это согласие NEBA — отдельно от
  согласия при входе в приложение.
- **«Забронировать»** (закреплена внизу) — недоступна, пока не заполнены имя,
  полный телефон, верная почта и галочка. Нажатие → крутилка в кнопке, кнопка
  неактивна, `POST /api/bookings`. Успех → 3.6, ошибка → таблица в 2.3.

### 3.6 «Вы записаны!»

- Большая галочка в круге, «Вы записаны!», серым «Запись подтверждена
  автоматически.» (можно добавить «Подтверждение отправили на почту»).
- Карточка: «Услуга», «Мастер», «Когда» — «Пятница, 16 октября, 10:00–11:00»,
  «Имя». Если `booking.membership` — строка «Оплата: по абонементу».
- «Добавить в календарь»: Google · Apple (.ics) · Outlook. Событие: название
  «<услуга> — NEBA», описание «Мастер: <имя>», место — адрес NEBA, время —
  Тбилиси: `${date}T${start}:00+04:00` … `${date}T${end}:00+04:00` (подходит
  к `src/lib/calendar.ts`).
- Кнопка «Записаться ещё раз» → начало раздела. Слоты — обновить.

### 3.7 Отмена и «Мои записи» (необязательно)

На витрине NEBA отмена — только по кнопке «Cancel booking» из письма (она
открывает booking.neba.space). Если нужна отмена в приложении:

- после записи сохранить `{ id, cancelToken, date, start, end, serviceId,
specialistId }`: просто — в localStorage (пропадёт при переустановке и не
  видно с другого устройства); надёжно — своя таблица в Supabase (миграция и
  RLS «своя строка», решение владельца);
- в списке обновлять статус через `lookup` (`booking: null` — отменена);
- «Отменить запись» → подтверждение «Отменить запись? Действие необратимо.» →
  `cancel-public` → «Запись отменена. Вы можете записаться снова в любое
  время.»

## 5. Модуль API — готовый код

Положить как `apps/client/src/formats/packages/massage-api.ts`. Проверен:
`tsc --strict` с настройками `apps/client`, prettier проекта, и сквозной
прогон против кода сервера NEBA на копии боевого каталога и расписания
(каталог → слоты → запись → повтор даёт 409 → время пропало из слотов →
lookup → отмена → lookup = null).

Запросы для TanStack Query (пример):

```ts
export const massageCatalogQuery = queryOptions({
  queryKey: ["massage", "catalog"],
  queryFn: fetchMassageCatalog,
  staleTime: 10 * 60_000,
  meta: { persist: false }, // ~550 КБ картинок — не в localStorage
});

export const massageSlotsQuery = queryOptions({
  queryKey: ["massage", "slots"],
  queryFn: () => fetchMassageSlots(62),
  staleTime: 60_000,
  meta: { persist: false },
});
// после записи и после 409: queryClient.invalidateQueries({ queryKey: ["massage", "slots"] })
```

Язык для `pickLoc` и `lang` в записи — `useI18n().locale` (`en | ka | ru`,
совпадает с языками NEBA).

```ts
export class MassageApiError extends Error {
  constructor(
    message: string,
    /** 400 — неверные данные, 409 — время заняли / запись закрыта, 0 — нет сети. */
    readonly status: number,
  ) {
    super(message);
  }
}

async function api<T>(path: string, init?: RequestInit): Promise<T> {
  let res: Response;
  try {
    res = await fetch(MASSAGE_API + path, {
      ...init,
      headers: { "Content-Type": "application/json", ...init?.headers },
    });
  } catch {
    throw new MassageApiError("network", 0);
  }
  const text = await res.text();
  let body: unknown = null;
  try {
    body = text ? JSON.parse(text) : null;
  } catch {
    // не JSON — ниже ошибка по статусу
  }
  if (!res.ok) {
    const message = (body as { error?: string } | null)?.error ?? `HTTP ${res.status}`;
    throw new MassageApiError(message, res.status);
  }
  return body as T;
}

  lang: MassageLang;
};

  req: MassageBookingRequest,

  return api("/api/bookings", {

export function lookupMassageBooking(id: string, token: string) {

// --- Тексты и форматирование ---

/** Текст на языке клиента: язык → английский → русский → грузинский. */
export function pickLoc(v: Loc, lang: MassageLang): string {
  if (!v) return "";
  if (typeof v === "string") return v;
  return v[lang] || v.en || v.ru || v.ka || "";
}

export function specialistName(sp: MassageSpecialist, lang: MassageLang): string {
  return `${pickLoc(sp.firstName, lang)} ${pickLoc(sp.lastName, lang)}`.trim();
}

/** «10:00» + 60 → «11:00». */
export function addMinutes(hhmm: string, minutes: number): string {
  const [h, m] = hhmm.split(":").map(Number);
  const t = Math.min(24 * 60, h * 60 + m + minutes);
  return `${String(Math.floor(t / 60)).padStart(2, "0")}:${String(t % 60).padStart(2, "0")}`;
}

/** 'YYYY-MM-DD' + n дней. */
export function addDays(date: string, n: number): string {
  const [y, m, d] = date.split("-").map(Number);
  return new Date(Date.UTC(y, m - 1, d + n)).toISOString().slice(0, 10);
}

/** Средняя оценка и число отзывов мастера (звёзды на карточке). */
export function ratingOf(
  reviews: MassageReview[],
  specialistId: string,
): { avg: number; count: number } {
  const own = reviews.filter((r) => r.specialistId === specialistId);
  if (own.length === 0) return { avg: 0, count: 0 };
  return { avg: own.reduce((s, r) => s + r.rating, 0) / own.length, count: own.length };
}

// --- Что показывать на шагах (всё считается по ответу /api/slots) ---

function startsOf(slots: SlotMap, specialistId: string, serviceId: string, date: string): string[] {
  return slots[specialistId]?.[serviceId]?.[date] ?? [];
}

/** Активные сначала, деактивированные — в конце (их видно, но выбрать нельзя). */
function activeFirst(list: MassageSpecialist[]): MassageSpecialist[] {
  return [...list.filter((sp) => !sp.inactive), ...list.filter((sp) => sp.inactive)];
}

/** Мастера, делающие услугу (порядок — как в админке NEBA). */
export function specialistsDoing(cat: MassageCatalog, serviceId: string): MassageSpecialist[] {
  return activeFirst(cat.specialists.filter((sp) => sp.serviceIds.includes(serviceId)));
}

/** Все мастера для шага «Мастер» без выбранной услуги. */
export function allSpecialists(cat: MassageCatalog): MassageSpecialist[] {
  return activeFirst(cat.specialists);
}

/** Услуги мастера (порядок — как в админке NEBA). */
export function servicesOf(cat: MassageCatalog, specialistId: string): MassageService[] {
  const sp = cat.specialists.find((s) => s.id === specialistId);
  return sp ? cat.services.filter((s) => sp.serviceIds.includes(s.id)) : [];
}

/** Свободные времена на дату при текущем выборе (мастер и/или услуга могут быть не выбраны). */
export function startsFor(
  cat: MassageCatalog,
  slots: SlotMap,
  date: string,
  sel: MassageSelection,
): string[] {
  const set = new Set<string>();
  for (const sp of cat.specialists) {
    if (sp.inactive || (sel.specialistId && sp.id !== sel.specialistId)) continue;
    for (const serviceId of sp.serviceIds) {
      if (sel.serviceId && serviceId !== sel.serviceId) continue;
      for (const s of startsOf(slots, sp.id, serviceId, date)) set.add(s);
    }
  }
  return [...set].sort();
}

/** Есть ли в этот день свободное время (подсветка дня в календаре). */
export function dayAvailable(
  cat: MassageCatalog,
  slots: SlotMap,
  date: string,
  sel: MassageSelection,
): boolean {
  return startsFor(cat, slots, date, sel).length > 0;
}

/** Свободен ли мастер под услугу в дату и время. */
export function specialistFreeAt(
  slots: SlotMap,
  specialistId: string,
  serviceId: string,
  date: string,
  start: string,
): boolean {
  return startsOf(slots, specialistId, serviceId, date).includes(start);
}

/** Услуги, на которые можно записаться в дату и время (есть свободный мастер). */
export function servicesBookableAt(
  cat: MassageCatalog,
  slots: SlotMap,
  date: string,
  start: string,
): MassageService[] {
  return cat.services.filter((svc) =>
    cat.specialists.some(
      (sp) => !sp.inactive && specialistFreeAt(slots, sp.id, svc.id, date, start),
    ),
  );
}

/**
 * Ближайшее время мастера для карточки: первый день со свободным временем и
 * первые count времён. Без выбранной услуги — по самой длинной услуге мастера:
 * тогда время подойдёт под любую его услугу, выбранную позже.
 */
export function nearestSlots(
  cat: MassageCatalog,
  slots: SlotMap,
  specialistId: string,
  serviceId?: string,
  count = 5,
): { date: string; starts: string[] } | null {
  let svcId = serviceId;
  if (!svcId) {
    const own = servicesOf(cat, specialistId);
    if (own.length === 0) return null;
    svcId = own.reduce((a, b) => (b.durationMin > a.durationMin ? b : a)).id;
  }
  const byDate = slots[specialistId]?.[svcId] ?? {};
  const first = Object.keys(byDate).sort()[0];
  return first ? { date: first, starts: byDate[first].slice(0, count) } : null;
}
```

## 6. Где в приложении

Раздел массажа — решение владельца (отдельный роут, например `/massage`, или
вход из «Студии»). Только пакетная сборка: показывать при `IS_PACKAGES`
(`src/lib/terms.ts`), в подписочном приложении (app.base40.fit) записи на
массаж нет — его адрес серверу NEBA не разрешён.

Запросы — только из браузера (`useQuery` на клиенте), не из SSR: CORS тут ни
при чём, но серверу приложения незачем ходить в NEBA, а данные зависят от
текущего времени.

## 7. Разработка и проверка

- **Локально — мок NEBA**, а не боевой сервер: с `localhost` боевой сервер
  запросы не примет (CORS), а каждая тестовая запись на нём — настоящая
  запись с письмами сотрудникам и мастеру.

  ```bash
  # пока ветка claude/kind-curie-w0xxhu не слита в main — клонировать её (-b …)
  git clone -b claude/kind-curie-w0xxhu https://github.com/borinsobaka-lab/booking-system
  cd booking-system/worker
  curl -s https://booking-system.borin-sobaka.workers.dev/api/public > seed.json
  node mock-server.mjs seed.json        # http://localhost:8787, те же обработчики, данные в памяти
  ```

  В `apps/client/.env.local`: `VITE_MASSAGE_API_BASE=http://localhost:8787`.
  Мок — тот же код сервера с живым каталогом и расписанием (занятость
  обезличена), писем не шлёт, всё стирается при перезапуске. До обновления
  боевого сервера `seed.json` можно взять и оттуда — `/api/public` там уже есть.

- **На проде** (после выкатки) — одна запись на себя с именем «ТЕСТ» и сразу
  отмена; владельцу NEBA сказать заранее — сотрудникам придут письма.
