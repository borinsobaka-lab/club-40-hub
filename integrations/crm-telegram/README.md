# Личный Telegram для CRM (`integrations/crm-telegram`)

Сервис держит вход в личные аккаунты Telegram (не боты) и соединение с
Telegram по протоколу MTProto (библиотека GramJS). Через него CRM админки
получает личные сообщения аккаунту, отвечает от его имени и пишет клиентам
первой — по номеру телефона или @нику.

Отдельный сервис, а не часть админки, потому что соединение с Telegram
должно быть одно и постоянное: тот же вход с двух соединений сразу Telegram
сбрасывает, а админка при каждой выкладке на время работает в двух
контейнерах.

**На настоящем аккаунте не проверен**: из среды разработки серверы Telegram
недоступны. Логика (вход, пересылка, отправка, предел новых чатов) покрыта
тестами с подставным соединением; первая проверка — вход владельца.

## Как устроено

```
Telegram ⇄ crm-telegram (вход, сессии в /data) ⇄ админка (/api/crm/tg-user) ⇄ база
```

- Вход: админка («CRM» → «Настройки» → «Каналы» → «Telegram (личный)»)
  передаёт сервису номер, затем код из Telegram и, если включён, облачный
  пароль. Код и пароль не сохраняются; сессия — в `/data/accounts.json`.
- Входящее личное сообщение (и сообщение, которое владелец отправил с
  телефона) сервис пересылает админке: `POST {ADMIN_URL}/api/crm/tg-user`,
  multipart (`meta` — JSON, `file` — вложение до 20 МБ), заголовок
  `Authorization: Bearer <CRM_TG_SECRET>`. Группы, каналы и боты не
  пересылаются.
- Админка зовёт сервис с тем же секретом: `GET /accounts/:id` (состояние),
  `POST /accounts/:id/login | code | password`, `POST /accounts/:id/send`,
  `POST /accounts/:id/resolve` (найти человека, чтобы написать первым),
  `DELETE /accounts/:id` (выйти и стереть сессию). `GET /health` — открыт.
- Новых чатов в сутки с аккаунта — не больше `NEW_CHATS_PER_DAY` (20):
  массовые сообщения незнакомым Telegram считает спамом и блокирует аккаунт.

## Переменные окружения

| Переменная          | Что это                                                            |
| ------------------- | ------------------------------------------------------------------ |
| `TELEGRAM_API_ID`   | `api_id` приложения с https://my.telegram.org → API development tools |
| `TELEGRAM_API_HASH` | `api_hash` оттуда же (секрет)                                      |
| `CRM_TG_SECRET`     | общий секрет с админкой, от 24 символов (секрет)                   |
| `ADMIN_URL`         | адрес админки, `https://admin.base40.fit`                          |
| `DATA_DIR`          | где хранить сессии, по умолчанию `/data`                           |
| `NEW_CHATS_PER_DAY` | предел новых чатов в сутки на аккаунт, по умолчанию 20             |
| `PORT`              | по умолчанию 3000                                                  |

У админки (`club40-admin`): `CRM_TG_URL` — адрес этого сервиса и
`CRM_TG_SECRET` — тот же секрет.

## Установка в Coolify

1. Новый ресурс из этого репозитория, ветка `main`: Base Directory `/`,
   Dockerfile Location `/integrations/crm-telegram/Dockerfile`, Watch Paths
   `integrations/crm-telegram/**`, порт 3000.
2. Persistent Storage: том с путём `/data` (без него вход теряется при
   каждом деплое).
3. Ровно один экземпляр (без масштабирования).
4. Переменные из таблицы выше. Домен — например `https://tg.base40.fit`
   (сервис отвечает только на запросы с секретом).
5. У `club40-admin` задать `CRM_TG_URL` и `CRM_TG_SECRET`, передеплоить.
6. Владелец входит в аккаунт в настройках CRM.

Пошагово для браузерного агента — AGENT_TASKS.md, Задача 18, часть В.

## Разработка

```
cd integrations/crm-telegram
bun install
bun test          # логика с подставным соединением
bunx tsc --noEmit
```

Файл `/data/accounts.json` — это вход в аккаунты: в репозиторий и в чат не
попадает, резервную копию тома хранить как секрет.
