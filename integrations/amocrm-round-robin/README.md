# Очередь ответственных amoCRM

Расширение для amoCRM: каждая **новая сделка** получает ответственного **по
очереди** из сотрудников, выбранных в настройках виджета. Первая сделка —
первому, вторая — второму, после последнего — снова первому. Пользователи
amoCRM не из списка новых сделок не получают.

Не связано с админкой и клиентским приложением Base40: своя папка, свой
сервер, общего кода нет.

## Как устроено

```
amoCRM ──вебхук «сделка добавлена»──▶ сервер очереди ──PATCH responsible_user_id──▶ amoCRM
   ▲                                       │
   └── окно настроек виджета ◀── статус ───┘   (кто следующий, последние сделки)
```

- **Виджет** (`widget/`): в amoCRM → Настройки → Интеграции → окно
  виджета выбирают сотрудников и порядок очереди (↑ ↓ ✕, «Добавить»), и
  отметку «Не трогать сделки, созданные вручную». Выбор хранится в самой
  amoCRM, в скрытом поле виджета `rr_config`
  (`{"users": [id, …], "skip_manual": bool}`). Там же видно, кто получит
  следующую сделку, и журнал последних сделок.
- **Сервер** (`server/`, Bun + SQLite): при установке интеграции получает
  OAuth-доступ к аккаунту и сам подписывается на вебхуки `add_lead` и
  `status_lead`. На каждую новую сделку читает настройки виджета через API
  (`GET /api/v4/widgets/{code}`, кэш 10 с) и ставит следующего по очереди.
  amoCRM работает без открытого браузера: распределение идёт и ночью.

Правила очереди (`server/src/round-robin.ts`, `processor.ts`):

- Очередь хранит, кто получил последнюю сделку. Список поменяли (добавили,
  убрали, переставили) — очередь продолжается со следующего после него.
- Отключённого в amoCRM пользователя очередь пропускает (в окне виджета —
  пометка «отключён в amoCRM»).
- Повтор вебхука (amoCRM повторяет, если не дождался ответа) очередь не
  двигает: каждая сделка назначается один раз.
- «Неразобранное»: приходит ли по нему `add_lead`, amoCRM не документирует,
  поэтому сервер ловит и принятие заявки (смена этапа из «Неразобранного»).
  Не видел сделку раньше — назначает по очереди; уже назначил, а при
  принятии ответственный сменился — возвращает назначенного.
- «Не трогать созданные вручную»: сделка с `created_user_id` сотрудника не
  перераспределяется (у заявок с сайта, из форм и т. п. он 0). Принятые из
  «Неразобранного» распределяются всегда.
- Очередь пуста или ошибка amoCRM (после 3 попыток) — сделка остаётся как
  была, запись в журнале окна виджета.

## Что нужно

- Тариф amoCRM **«Расширенный» или «Профессиональный»** — подписка на
  вебхуки через API есть только на них. На «Базовом» сервер не сможет
  подписаться; окно виджета покажет адрес, который можно попробовать добавить
  вручную (Настройки → Интеграции → Веб-хуки, события «Сделка добавлена» и
  «Смена этапа сделки»).
- Устанавливает интеграцию **администратор** amoCRM: токен получает его
  права, а вебхуки и список пользователей API отдаёт только администратору.
- Сервер с HTTPS-адресом, доступным из интернета (например, Coolify).

## Установка

Порядок важен: адрес сервера нужен и amoCRM, и архиву виджета, а ключи
интеграции — серверу.

1. **Выбрать адрес сервера**, например `https://rr.base40.fit`, и направить
   его DNS на сервер Coolify.
2. **Создать интеграцию в amoCRM**: Настройки → Интеграции → «Создать
   интеграцию» (своя, внешняя).
   - Ссылка для перенаправления: `https://rr.base40.fit/oauth/callback`
   - Ссылка для хука об отключении: `https://rr.base40.fit/disable`
   - Доступ: «Доступ к данным аккаунта».
   - Название и описание — на русском (в архиве виджета только `ru`).
3. **Собрать архив виджета** и загрузить его в интеграцию (вкладка с
   архивом виджета):

   ```bash
   bash integrations/amocrm-round-robin/scripts/build-widget.sh https://rr.base40.fit
   # → integrations/amocrm-round-robin/widget.zip
   ```

4. **Скопировать из интеграции** (вкладка «Ключи и доступы»): «ID
   интеграции», «Секретный ключ» и код виджета.
5. **Развернуть сервер в Coolify** — новый ресурс из этого репозитория,
   ветка `main`:
   - Base Directory `/`, Dockerfile Location
     `/integrations/amocrm-round-robin/server/Dockerfile`
   - Watch Paths `integrations/amocrm-round-robin/server/**`
   - Домен `https://rr.base40.fit`, порт 3000
   - **Persistent Storage**: путь `/data` (токены, очередь и журнал;
     без тома при каждом деплое всё обнуляется и интеграцию придётся
     переустанавливать)
   - Переменные окружения:

     | Переменная          | Значение                                         |
     | ------------------- | ------------------------------------------------ |
     | `PUBLIC_URL`        | `https://rr.base40.fit`                          |
     | `AMO_CLIENT_ID`     | ID интеграции                                    |
     | `AMO_CLIENT_SECRET` | Секретный ключ                                   |
     | `AMO_WIDGET_CODE`   | Код виджета                                      |
     | `AMO_REDIRECT_URI`  | необязательно; по умолчанию `PUBLIC_URL/oauth/callback` |

   Проверка: `https://rr.base40.fit/health` отвечает `ok`.
6. **Установить виджет** в amoCRM (Настройки → Интеграции → виджет →
   «Установить») и выдать доступ. Сервер сохранит токены и подпишется на
   вебхуки.
7. **Открыть настройки виджета**, добавить сотрудников, расставить порядок,
   «Сохранить». В блоке «Состояние» должно быть «Подключено». Завести
   тестовую заявку — ответственный сменится, сделка появится в журнале.

Обновление виджета: поднять `version` в `widget/manifest.json`, собрать архив
и загрузить заново. Сервер обновляется деплоем.

## Разработка

```bash
cd integrations/amocrm-round-robin/server
bun install
bun test           # очередь, разбор вебхука, токены, сквозной сценарий с подделкой amoCRM
bun run typecheck
```

Адреса сервера:

| Адрес                  | Кто вызывает                                         |
| ---------------------- | ---------------------------------------------------- |
| `GET /health`          | Coolify (HEALTHCHECK)                                |
| `GET /oauth/callback`  | amoCRM при установке (код обменивается только с доменами amoCRM/Kommo) |
| `POST /webhook/{секрет}` | вебхук amoCRM; секрет в адресе — свой у аккаунта   |
| `GET /disable`         | хук отключения интеграции (подпись HMAC секретным ключом) |
| `/api/status`, `/api/saved`, `/api/resubscribe` | окно виджета через `$authorizedAjax` (одноразовый JWT, CORS только с доменов amoCRM) |

Не проверено на живом аккаунте (документация amoCRM молчит): приходит ли
`add_lead` по «Неразобранному» (обработаны оба случая) и обязателен ли блок
`tour` в манифесте закрытой интеграции (он есть).
