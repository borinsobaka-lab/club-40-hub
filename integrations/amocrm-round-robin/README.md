# Очередь ответственных amoCRM

Расширение для amoCRM: **триггер цифровой воронки** «Очередь
ответственных». Владелец ставит его на нужный этап воронки и выбирает
условие amoCRM («при создании в этапе», «при переходе в этап» и т. п.) —
сделки в этом этапе получают ответственного **по очереди** из сотрудников,
выбранных в настройках виджета. Первая сделка — первому, вторая — второму,
после последнего — снова первому. Этапы без триггера не трогаются;
пользователи amoCRM не из списка сделок не получают.

Не связано с админкой и клиентским приложением Base40: своя папка, свой
сервер, общего кода нет.

## Как устроено

```
amoCRM ──триггер воронки, POST /dp──▶ сервер очереди ──PATCH responsible_user_id──▶ amoCRM
   ▲                                       │
   └── окно настроек виджета ◀── статус ───┘   (кто следующий, последние сделки)
```

- **Виджет** (`widget/`): в amoCRM → Настройки → Интеграции → окно
  виджета выбирают сотрудников и порядок очереди (↑ ↓ ✕, «Добавить»), и
  отметку «Не трогать сделки, созданные вручную». Выбор хранится в самой
  amoCRM, в скрытом поле виджета `rr_config`
  (`{"users": [id, …], "skip_manual": bool}`). Там же видно, кто получит
  следующую сделку, и журнал последних сделок. Плюс действие цифровой
  воронки (`manifest.json` → `locations: digital_pipeline`, блок `dp` с
  `webhook_url` = `{сервер}/dp`); своих настроек у триггера нет — очередь
  одна на аккаунт.
- **Сервер** (`server/`, Bun + SQLite): при установке интеграции получает
  OAuth-доступ к аккаунту (вебхук аккаунта **не** создаёт — с 2026-10-20
  распределяются только сделки из этапов с триггером). Сработал триггер —
  amoCRM шлёт `POST /dp` (JSON или form-urlencoded: `event.data.id`,
  `element_type`, `status_id`, `pipeline_id`, `account_id`), сервер сразу
  отвечает 200, читает сделку и настройки виджета через API
  (`GET /api/v4/widgets/{code}`, кэш 10 с) и ставит следующего по очереди.
  amoCRM работает без открытого браузера: распределение идёт и ночью.

Правила очереди (`server/src/round-robin.ts`, `processor.ts`):

- Очередь хранит, кто получил последнюю сделку. Список поменяли (добавили,
  убрали, переставили) — очередь продолжается со следующего после него.
- Отключённого в amoCRM пользователя очередь пропускает (в окне виджета —
  пометка «отключён в amoCRM»).
- Подписи у запроса воронки нет. Защита: только подключённые `account_id`,
  только сделки (`element_type = 2`), сделку сервер сначала читает через API
  (нет в аккаунте или другая воронка — пропуск, только в лог). Первые 20
  запросов `/dp` после запуска пишутся в лог целиком.
- Повтор события (amoCRM повторяет до 4 раз в час) очередь не двигает:
  сделка в одном этапе назначается один раз (`dp_events`: сделка × этап).
  Та же сделка дошла до другого этапа с триггером — новое назначение.
- «Неразобранное»: заявка попадает в этап при принятии — триггер с условием
  «при переходе в этап» (или «при создании») на первом этапе её поймает.
- «Не трогать созданные вручную»: сделка с `created_by` сотрудника и без
  источника (`source_id`) не перераспределяется (у заявок с сайта, из форм,
  чатов и «Неразобранного» — распределяется).
- Очередь пуста или ошибка amoCRM (после 3 попыток) — сделка остаётся как
  была, запись в журнале окна виджета.

## Что нужно

- Тариф amoCRM с цифровой воронкой (триггеры виджетов в настройках воронки).
- **Приватная интеграция** в amoCRM (во «внешнюю» архив виджета не
  загружается). Перед ней amoCRM просит заявление на кастомизацию аккаунта
  и время на его одобрение.
- Устанавливает интеграцию **администратор** amoCRM: токен получает его
  права, а вебхуки и список пользователей API отдаёт только администратору.
- Сервер с HTTPS-адресом, доступным из интернета (например, Coolify).

## Установка

Пошаговая инструкция для браузерного агента — **AGENT_TASKS.md** в корне
репозитория, Задача 15. Коротко:

1. DNS: `rr.base40.fit` → сервер Coolify.
2. **Coolify** — новый ресурс из этого репозитория, ветка `main`:
   - Base Directory `/`, Dockerfile Location
     `/integrations/amocrm-round-robin/server/Dockerfile`
   - Watch Paths `integrations/amocrm-round-robin/server/**` и
     `integrations/amocrm-round-robin/widget/**`
   - Домен `https://rr.base40.fit`, порт 3000
   - **Persistent Storage** с путём `/data` (токены, очередь и журнал; без
     тома при каждом деплое всё обнуляется и интеграцию придётся
     переустанавливать)
   - `PUBLIC_URL=https://rr.base40.fit` — больше для первого запуска ничего
     не нужно. Проверка: `https://rr.base40.fit/` — страница сервера.
3. **amoCRM** → amoМаркет → «Создать интеграцию» (**приватная**; перед ней
   — заявление на кастомизацию аккаунта):
   ссылка для перенаправления `https://rr.base40.fit/oauth/callback`, хук
   об отключении `https://rr.base40.fit/disable`, доступ к данным аккаунта,
   архив виджета — скачать с `https://rr.base40.fit/widget.zip` (сервер
   собирает его сам, со своим адресом внутри).
4. Из интеграции («Ключи и доступы») — в переменные Coolify:

   | Переменная          | Значение                                                       |
   | ------------------- | -------------------------------------------------------------- |
   | `AMO_CLIENT_ID`     | ID интеграции                                                  |
   | `AMO_CLIENT_SECRET` | Секретный ключ                                                 |
   | `AMO_WIDGET_CODE`   | необязательно: сервер сам находит свой виджет по ID интеграции |
   | `AMO_REDIRECT_URI`  | необязательно; по умолчанию `PUBLIC_URL/oauth/callback`        |

   Перезапустить ресурс.

5. **Установить виджет** в amoCRM и выдать доступ — сервер сохранит токены.
6. **Настройки виджета**: сотрудники, порядок, «Сохранить». В блоке
   «Состояние» — «Подключено. Добавьте триггер в нужный этап воронки».
7. **Триггер**: Сделки → Настроить воронку → нужный этап → «+ Добавить
   триггер» → «Очередь ответственных» → условие → «Готово» → «Сохранить».

Архив можно собрать и локально:
`bash integrations/amocrm-round-robin/scripts/build-widget.sh https://rr.base40.fit`.

Обновление виджета: поднять `version` в `widget/manifest.json`, собрать архив
и загрузить заново. Сервер обновляется деплоем.

## Разработка

```bash
cd integrations/amocrm-round-robin/server
bun install
bun test           # очередь, разбор события воронки, токены, сквозной сценарий с подделкой amoCRM
bun run typecheck
```

Адреса сервера:

| Адрес                               | Кто вызывает                                                                         |
| ----------------------------------- | ------------------------------------------------------------------------------------ |
| `GET /health`                       | Coolify (HEALTHCHECK)                                                                |
| `GET /`, `/widget.zip`, `/logo.png` | страница проверки; архив виджета и логотип для интеграции в amoCRM                   |
| `GET /oauth/callback`               | amoCRM при установке (код обменивается только с доменами amoCRM/Kommo)               |
| `POST /dp`                          | триггер цифровой воронки (JSON или form-urlencoded), ответ 200 сразу                 |
| `GET /disable`                      | хук отключения интеграции (подпись HMAC секретным ключом)                            |
| `/api/status`, `/api/saved`         | окно виджета через `$authorizedAjax` (одноразовый JWT, CORS только с доменов amoCRM) |

Не проверено на живом аккаунте (документация amoCRM молчит или
противоречит себе): Content-Type запроса `/dp` (принимаются оба), место
`action_multiple` в манифесте (сделано как в примере — рядом с
`dp.settings`), обязателен ли блок `tour` в манифесте закрытой интеграции
(он есть).
