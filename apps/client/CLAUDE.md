# Base40 — клиентское приложение (apps/client)

Мобильно-ориентированное веб-приложение для клиентов студии (в планах — PWA).
TanStack Start (SSR) + React 19 + Tailwind 4 + shadcn/radix. Пакетный
менеджер — bun.

Это часть монорепозитория: общие правила (рабочий режим, деплой, форматы
студий, база данных и модель доступа) — в корневом `CLAUDE.md`. Админка —
`apps/admin`. Оба приложения работают с одной базой Supabase; **схема БД
ведётся в `db/` в корне репозитория (новые изменения — `db/migrations/`)** — в
`apps/client` файлов схемы нет и быть не должно.

## Два приложения — два формата студий

Студии бывают двух форматов: «Зал с подписочной моделью» (`subscription`) и
«Зал с пакетами тренировок» (`packages`, в разработке). Подробно —
**STUDIO_FORMATS.md в корне репозитория**. Из `apps/client` собираются **два
приложения**: app.base40.fit (подписочный, `VITE_APP_FORMAT` не задан) и
app.lady-stretch.one (до 2026-10-12 — pack.base40.fit, `VITE_APP_FORMAT=packages`) —
`src/lib/app-format.ts` (`APP_FORMAT`, `FORMAT_APP_URL`). Деплой второго —
DEPLOY.md, раздел «Второе приложение».

- Подписочное приложение не ломаем: экраны пакетного формата — в
  `src/formats/packages/` (расписание, «Студия», абонементы, карточка
  тренировки, переключатель студий), роут выбирает компонент по
  `IS_PACKAGES` (`src/lib/terms.ts`); общие экраны (вход, профиль, новости) —
  общие, различия в них — через `IS_PACKAGES`. Подробно — STUDIO_FORMATS.md,
  «Пакетное приложение».
- Слово «клуб» в текстах: в пакетном приложении — «студия» (решение
  владельца 2026-10-11), подстановка — `CLUB.gen`/`CLUB.prep`/… из
  `src/lib/terms.ts`; новый текст с «клубом» — сразу через `CLUB`.
- Регистрации нет (решение владельца 2026-10-11) — см. «Авторизация».
- Клиент студии другого формата видит экран «Ваша студия — в другом
  приложении» (`OtherAppScreen` в `__root.tsx`, студия — `useClientStudio`).
- Фирменный цвет — по формату приложения: `--brand`/`--brand-foreground` в
  `src/styles.css`, атрибут `data-app-format` на `<html>` (`RootShell` в
  `__root.tsx`). Подписочное — `#FFD900`, текст на кнопках тёмно-серый
  `#333`; пакетное — `#F763FC`, текст белый (решение владельца 2026-10-11).
  `--primary` = `--brand`; цвета бренда в коде не хардкодить — только
  `primary`/`primary-foreground` (огоньки шапки в пакетном — свои цвета
  `--blob` в конце `styles.css`, свечение кнопки ассистента — `hue-rotate`).
  Цвет и логотип студии (`studios.brand_color`/`logo_url`) приходят, но не
  применяются.
- Надписей заглавными буквами (`uppercase`, капс в тексте) нет — заголовки и
  подписи пишутся «как в предложении» (решение владельца 2026-10-11).
- Заголовки (h1–h3: страницы, разделы, онбординг) — `font-semibold` (600),
  не `font-black`/`font-bold`: решение владельца 2026-10-11 «полегче».
  Цифры-акценты (цены, счётчики, линейка) остаются жирными.
- Поля ввода (решение владельца 2026-10-12, по образцу iOS-форм): без рамки
  и тени, фон чуть серее белого (`bg-field`), в фокусе — на тон темнее
  (`bg-field-focus`), подсказка светло-серая, высота 56px, скругление
  `rounded-2xl`. Общий класс `fieldClass` — `src/components/ui/input.tsx`,
  его берут `Input`, `Textarea`, поля с плавающей подписью и ячейки кода
  входа; цвета — токены `--field*` в `src/styles.css`. Новое поле — только
  через эти компоненты, без своих `border`/`ring`.
- Кнопки действий (решение владельца 2026-10-13) — одного размера во всём
  приложении: высота 48px, текст 16px полужирный (`font-semibold`; с
  2026-10-13 — тоньше прежнего `font-bold`), иконка 20px, скругление
  `rounded-full` — размер по умолчанию `Button` (`src/components/ui/button.tsx`).
  Свои `<button>`/`<a>` в виде кнопки — `className={cn(buttonVariants(), …)}`,
  без своих `h-*`, `text-*`, `font-*`; менять можно цвет и ширину.
- Телефон (решение владельца 2026-10-13) — только `PhoneInput`
  (`src/components/ui/phone-input.tsx`): флаг и код страны (по умолчанию
  Грузия, +995; код стирается и вводится другой), номер с маской
  «___ __ __ __» у грузинского; значение — строка «+995 591 09 97 19»,
  проверка — `isValidPhone`, разбор старых номеров — `parsePhone`
  (`src/lib/phone.ts`, тесты рядом). Автозаполнение —
  `tel-country-code` + `tel-national`, номер целиком из автоподстановки
  разбирается сам. Почта — `type="email"`, `autoComplete="email"`,
  `name="email"`, без автозаглавной и автозамены.
- Пока в базе нет `db/migrations/2026-10-09_studio_formats.sql`, запросы к `studios` падают — хуки
  отдают undefined, и приложение работает как до разделения форматов.

## Языки (решение владельца 2026-10-12)

Приложение на трёх языках: **английский — по умолчанию** (его видят при
первом открытии), грузинский и русский. На экране входа справа от
логотипа — компактная плашка «флаг в кружке + название», по нажатию —
выпадающий список (`LanguageSwitcher`); в профиле — строка «Язык» как
остальные кнопки (справа — текущий язык), по нажатию — шторка со списком
(`LanguageSheet`); оба — `components/language-switcher.tsx` (решения
владельца 2026-10-12). Ядро — `src/i18n/`.

- **Строки интерфейса.** Исходный язык кода — русский: `const t = useT();`
  → `t("Записаться")`, подстановки `t("Осталось {n} мест", { n })`, число
  со словом — `t.plural(n, "{n} тренировка|{n} тренировки|{n} тренировок")`
  (русские формы 1|2|5; в переводе свои: en «{n} workout|{n} workouts», ka —
  одна форма). Подписи в константах — `msg("…")`, переводятся при показе
  `t(label)`; вне компонентов (только в браузере) — `currentT()`; в `head`
  роута — `getTranslator(match.context.locale)`. Даты, время и числа — `t.date(d, {…})`,
  `t.time(d)`, `t.number(n)` (`src/i18n/format.ts`), не
  `toLocaleString("ru-RU")`: в Chrome нет грузинских данных Intl (ka-GE
  молча становится английским), там дата собирается из своих грузинских
  названий. Ключ — русский текст целиком
  литералом (без `${}`): «клуб/студия» — две строки по `IS_PACKAGES`, а не
  `CLUB.*` внутри `t()`. Тексты, которые уходят в базу (причина отмены
  записи и т.п.), — по-русски: хранится ключ, показывается перевод.
- **Словари** — `src/i18n/dictionaries/{en,ka}/<раздел>.ts`: «русский текст
  → перевод», разделы по экранам, собираются в `index.ts`. Новая строка в
  коде = строка в обоих словарях; проверка — `bun run i18n:check` (нет
  перевода — выход 1; `--unused` — лишние ключи, `--leftovers [файлы]` —
  кириллица вне `t()`). Без перевода показывается русский оригинал.
- **Скорость.** Словарь каждого языка — отдельный чанк: телефон скачивает
  только выбранный (русскому не нужен никакой), поиск строки — обращение к
  объекту. Язык — cookie `lang` (не localStorage): сервер рендерит страницу
  сразу на нём (`beforeLoad` корня в `__root.tsx` читает cookie —
  `i18n/request-locale.ts` — и грузит словарь), браузер загружает тот же
  словарь до гидратации (`hydrate` в `router.tsx`) — без мелькания и
  расхождений. Смена языка — догрузка словаря и перерисовка, без
  перезагрузки и без запросов к базе.
- **Контент из админки** (новости, услуги, абонементы, тренировки, тренеры,
  название и адрес студии; тексты раздела «О нас» — в коде,
  `formats/packages/about-config.ts`, переводы — словарь `about.ts`): русский — в прежних колонках,
  переводы — `translations jsonb` той же строки
  (`db/migrations/2026-10-12_zzzzzz_content_translations.sql`,
  `{"en": {"title": "…"}, "ka": {…}}`; заполняются в админке переключателем
  языков в шапке окна редактирования). Показ — `const loc = useLocalize();`
  `loc(row).title` (`src/i18n/content.ts`: язык клиента → английский →
  русский). В select таких таблиц — колонка `translations`, иначе клиент
  увидит русский. Строка приходит со всеми языками, поэтому смена языка
  данные не перезапрашивает.

## Команды (из apps/client)

- `bun install` — зависимости (только публичный npm-реестр)
- `bun run dev` — дев-сервер на :8080 (из корня `bun run dev:client` — на :8081,
  чтобы не мешать админке)
- `bun run build` — прод-сборка (Nitro node-server → `.output/server/index.mjs`)
- `bunx tsc --noEmit` — типы; должен быть чистым перед коммитом
- `bun test` — тесты чистой логики (`*.test.ts` исключены из tsc, как в
  админке); импортируйте в них модули без запросов к базе: клиент Supabase
  без `.env` падает при импорте. Пакетное приложение —
  `formats/packages/packages-logic.test.ts` (роли «Студии», замены тренеров,
  следующие платежи).
- `bun run lint` — форматный долг снят (prettier прогнан целиком); остались
  содержательные замечания — чинить по ходу задач. Форматирование и
  содержательные правки — разными коммитами.

## Рабочий режим

Общий для монорепозитория — корневой `CLAUDE.md`. Если клиентскому коду нужна
новая схема (`db/migrations/`): миграцию выполняет мигратор при деплое
админки, поэтому сначала мержится миграция с админкой, после её деплоя —
клиентская часть. Пока у админки не задан `DATABASE_URL` — в отчёте явно
писать: «сначала выполнить SQL, потом мержить».

## Авторизация

Вход по email-коду (6 цифр — Supabase не даёт менять длину; константы
OTP_LENGTH и RESEND_COOLDOWN_SEC = 60 в src/routes/auth.tsx — повторная
отправка кода заблокирована на минуту с обратным отсчётом): `requestOtp`/`verifyOtp` в
`src/hooks/use-auth.tsx` (signInWithOtp / verifyOtp type=email).

**Регистрации нет** (решение владельца 2026-10-11): на экране входа только
почта. Войти может лишь член клуба, которого завели на портале (карточка
`clients` с этой почтой). `requestOtp` шлёт `shouldCreateUser: true` и
`app_format`: при первом входе GoTrue создаёт учётную запись, а триггер
`handle_new_user` (`db/migrations/2026-10-11_zzzzzzzzz_client_signin_only.sql`)
привязывает её к карточке или отказывает — GoTrue отвечает «Database error
saving new user», экран показывает «почта не найдена среди членов клуба».
Граница — в базе, не во фронтенде. Уже существующую учётную запись без
карточки (давнюю или после удаления клиента на портале) останавливают хук
писем (код не уходит, ошибка `not_a_club_member`) и `ensure_client_profile`
(`db/migrations/2026-10-12_client_account_wipe.sql`): приложение выходит
(`use-client-studio.ts`), экран входа показывает ту же «почта не найдена»
(`src/lib/sign-in-refused.ts`). `GOTRUE_DISABLE_SIGNUP` должен быть
`false`, иначе впервые войти нельзя. Выход — только этого приложения
(`signOut({ scope: "local" })`, `use-auth.tsx`, `use-client-studio.ts`):
учётная запись у сотрудника-клиента общая с админкой, глобальный выход
выкинул бы его и оттуда. После входа — онбординг (`/onboarding`,
`member_profiles`): ответы видны на портале в карточке клиента, вкладка
«Анкета». У пакетного приложения анкета своя —
`src/formats/packages/onboarding.tsx` (общие варианты ответов —
`src/components/onboarding.tsx`, тексты и типы — `src/lib/onboarding.ts`,
выбор — по `IS_PACKAGES` в `src/routes/onboarding.tsx`); оформлена как
разделы приложения (тёмная шапка с огоньками, белая панель, разделители
блоков) — каркас `src/formats/packages/dark-frame.tsx` (огоньки поверх
иллюстрации, высота — по `visualViewport`, чтобы клавиатура не закрывала
поля), в нём же экран входа
пакетного приложения (`src/routes/auth.tsx`, ветка `IS_PACKAGES`);
подробно — STUDIO_FORMATS.md.

**«Вход закрыт»** (решение владельца 2026-10-14: доступ к приложению
рассылают до переноса базы клиентов): `app_install_settings.sign_in_closed`
(переключатель в админке, «Мобильное приложение» → «Настройки», у app. и
pack. свой) — на экране входа вместо почты и согласия текст «Спасибо за
скачивание… Вход в приложение мы откроем утром, 18 октября». Флаг читает
`fetchAppInstall` (`src/lib/app-install.ts`, `select("*")` — до миграции не
падает) в loader корня — это только первое значение: страница может прийти
устаревшей (минутный кэш сервера, копия страницы в service worker), поэтому
экран входа сразу перепроверяет флаг в базе (`fetchSignInClosed`, React
Query): при открытии, при возвращении в приложение и, пока вход закрыт, раз
в 30 секунд. Уже начатый ввод кода доводится до конца. Граница — только экран: клиентов
без карточки и так не пускает база.

Салют на главной (решение владельца 2026-10-12) — после входа по коду и
после анкеты (анкета ведёт на главную, не в расписание): экран входа и
анкета ставят одноразовый флаг `queueHomeConfetti`, главная при открытии
стреляет (`fireQueuedHomeConfetti`, `src/lib/confetti.ts`). Новый клиент
после кода уходит в анкету — салют ждёт её конца и звучит один раз.

Паролей у клиентов НЕТ; настройка писем и длины кода в Supabase — см.
AUTH_SETUP.md в корне репозитория. Письма уходят с noreply@base40.fit через
Resend (хук в админке, `RESEND_API_KEY` у club40-admin).

## Политика конфиденциальности (решение владельца 2026-10-13)

Единственный юридический документ приложения **Lady Stretch** (только
пакетное; у Base40 в профиле — прежние «Правовые документы») — политика
конфиденциальности на английском (на любом языке интерфейса), под
законодательство Грузии; основа — прежняя политика Mobifitness без РФ;
операторы — ИП студий, исполнители по их офертам (Сабуртало — Vladimir
Borin, Ваке — Milana Shirshikova), совместные операторы общей системы;
оферты ссылаются на неё как на «Personal Data Confidentiality Policy»;
ссылок на сайт в тексте нет. Экран `/privacy`
(`src/routes/privacy.tsx`), открывается из профиля вместо «Правовых
документов» и **без входа** (`PUBLIC_ROUTES` в `__root.tsx`: без редиректа на
вход и без проверки анкеты). На экране входа под почтой — галочка «Принимаю
политику конфиденциальности и даю согласие на обработку персональных
данных» (`components/privacy-consent.tsx`; политика — в шторке, почта не
теряется); без неё код не запрашивается. После входа согласие пишется в
`user_metadata` учётной записи (`privacy_policy_version` — дата редакции,
`privacy_policy_accepted_at`; `lib/privacy-consent.ts`).
Текст — `src/components/privacy-policy.tsx` (без хуков, реквизиты — props),
реквизиты оператора и дата — `src/lib/legal.ts` (у подписочного — `null`:
ни строки в профиле, ни страницы). Услуги студии регулирует
публичная оферта на сайте — в политике только персональные данные. Новое,
что собирает приложение (поле анкеты, сервис-обработчик), — дописать в
разделы 4–8 политики.

## Данные и мультистудийность

- Студия клиента: `useClientStudioId()` (`src/hooks/use-client-studio.ts`) —
  clients.studio_id с кэшем; гость/нет карточки → null → запросы без фильтра
  (поведение одной студии). Контент (расписание, новости и услуги —
  `.contains("studio_ids", [studioId])`, кнопки главной) — по
  **смотримой** студии `useViewedStudioId()` (`src/hooks/use-viewed-studio.ts`):
  в пакетном приложении её выбирают на главной (переключатель, по умолчанию
  своя), в подписочном она всегда = своя. Своё (записи, абонементы клиента,
  срок отмены — `useClubSettings("home")`, проверка формата в `__root.tsx`)
  — по своей студии. Тарифы подписочного — по студии из карточки клиента
  (memberships.tsx). Номенклатура пакетного (`packCatalogQuery`) с
  2026-10-13 — общая для всех пакетных студий: отбор по формату студии
  строки (`studios!inner(format)`), не по смотримой студии
  (`db/migrations/2026-10-13_zzzz_packages_shared_catalog.sql`).
- «Мои записи» всегда фильтровать `.eq("user_id", user.id)` явно — RLS
  разрешает тренеру видеть все брони студии.
- Запись на тренировку — только через RPC `book_schedule_entry` /
  `cancel_schedule_booking` (атомарные, без овербукинга). Никаких прямых
  insert в schedule_bookings.
- «Контакты и правила» (ссылки кнопок главной, срок отмены записи) — свои у
  студии: `studio_app_settings`, хук `use-club-settings`; клиент без
  карточки — прежний синглтон `club_settings`.

## PWA

Установка на рабочий стол (2026-10-11): манифест собирается на лету —
`src/routes/manifest[.]webmanifest.ts`; иконка и подпись под значком —
из админки («Приложение» → «Настройки», `app_install_settings` — строка
на формат, `APP_FORMAT`; картинки — бакет `app-icons`), читает
`src/lib/app-install.ts` (минутный кэш в памяти, устаревший отдаётся сразу и
обновляется фоном; при ошибке — Base40 из `public/`).
В `<head>` их ставит loader корня (`__root.tsx`): фавикон,
`apple-touch-icon`, `apple-mobile-web-app-title` (подпись на iOS).
У app. и pack. — свои.

Только вертикальная ориентация (решение владельца 2026-10-13): в манифесте
`orientation: "portrait"` (Android); iOS его не читает — на повёрнутом
телефоне поверх экрана заглушка «Поверните телефон вертикально»
(`components/rotate-overlay.tsx`, показ — медиазапросом в конце
`styles.css`: сенсор, горизонталь, высота до 500px; планшеты не трогает).

Service worker — `public/sw.js`, пока только у пакетного приложения
(регистрация в `RootComponent`, `__root.tsx`, только в прод-сборке): файлы
`/assets/*` — из кэша телефона (имена с хэшем), страница — из сети (после
деплоя сразу новая версия), без сети или если сеть не ответила за 3 с —
сохранённая копия этой же страницы. Supabase (другой домен) не трогает.
Включить у подписочного — убрать `IS_PACKAGES` из условия регистрации.

## Скорость (решение владельца 2026-10-11: ускорить экраны и холодный запуск)

- **Данные — только через React Query**, не `useState` + `useEffect`: кэш
  переживает переход между разделами (`main` с `key={pathname}`
  пересоздаёт страницу) и сохраняется в localStorage между запусками —
  `src/lib/query-persist.ts` (по пользователю; при выходе и смене
  пользователя стирается, `use-auth.tsx`; сбрасывается каждым деплоем через
  `__BUILD_ID__`, кроме запросов с `meta: { persist: "stable" }` — студия
  клиента). Настройки по умолчанию — `src/router.tsx` (staleTime 30 с).
  Не сохранять — `meta: { persist: false }`.
- Запросы, которые нужны и экрану, и фоновой подгрузке, — фабрики
  `queryOptions`: `src/formats/packages/queries.ts` (расписание, абонементы,
  «Студия»), `src/lib/client-card.ts` (карточка клиента — общая у главной и
  «Профиля»), `src/lib/home-queries.ts` (записи на главной и история
  посещений — плашка под ними, шторка `components/visit-history-drawer.tsx`:
  журнал `bookings_log`, а не записи с занятием — отменённое студией и
  персональное клиенту по RLS не видны). После действий
  (запись, отмена) — `setQueryData` своего кэша и `invalidateQueries`
  соседних экранов, а не перезагрузка.
- `usePrefetchScreens` (`__root.tsx`): карточка и записи главной — сразу
  после входа, параллельно с проверкой анкеты; код остальных разделов и (в
  пакетном) их данные — фоном, когда первый экран догрузился.
- Холодный запуск не ждёт сети: пользователь берётся из сохранённой сессии
  supabase-js (`readStoredSession`, `use-auth.tsx`) — запросы сами дождутся
  обновления токена, а недействительная сессия уводит на вход; пройденная
  анкета запоминается на телефоне (`base40.onboarded`, `__root.tsx`).
- Сервер: заранее сжатые `.br`/`.gz` копии бандла (`compressPublicAssets`
  в `vite.config.ts`), preconnect к API Supabase в `<head>`; иконка
  приложения (`app-install.ts`) не задерживает серверный рендер.
- Картинки в бандле — растр разумного размера (заглушка шторки тренировки
  `brand-placeholder.webp` — 11 КБ вместо прежнего SVG на 1,4 МБ).
- Плавная прокрутка (жалоба владельца 2026-10-12 «скролл подтормаживает»):
  огоньки шапки (`.gradient-blobs`) анимируются бесконечно и видны за
  каждым разделом, поэтому на них и на том, что над ними, — никаких
  `filter` (`blur`, `hue-rotate`), `backdrop-filter`/`backdrop-blur` и
  `mask-image`: телефон пересчитывал бы их каждый кадр. Размытый огонёк
  нарисован градиентом, плавный низ слоя — цветом подложки поверх
  (`.backdrop-fade`), плашки в шапке — просто `bg-white/10`. Стекло
  (`glass-dark`) осталось только у нижнего меню; маска с «дыркой» над
  огоньками — только в `DarkFrame` (вход, анкета). Сетевые картинки в
  списках — `loading="lazy" decoding="async"`.
