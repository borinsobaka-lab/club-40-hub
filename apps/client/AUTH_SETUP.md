# Настройка почтовой авторизации (noreply@base40.fit)

Код приложений уже готов: клиентское приложение шлёт и проверяет настоящий
4-значный код, админка после пароля отправляет magic-ссылку. Ниже — шаги в
Supabase Dashboard (проект `lyvarbqquvgxufmqgyix`), без которых письма будут
уходить с дефолтного адреса Supabase и с 6-значным кодом.

## 1. SMTP (если ещё не доделано)

**Authentication → Emails → SMTP Settings** (или Project Settings → Auth):

- Enable Custom SMTP: **on**
- Sender email: `noreply@base40.fit`, Sender name: `CLUB 40`
- Host/Port/User/Password — из Resend: host `smtp.resend.com`, port `465`,
  user `resend`, password = API-ключ Resend.
- В Resend домен `base40.fit` должен быть верифицирован (SPF + DKIM записи
  в Cloudflare DNS — Resend показывает их на странице домена, статус должен
  быть Verified, иначе письма попадут в спам или не уйдут).

## 2. Длина кода — 4 цифры

**Authentication → Sign In / Up → Email** (настройки Email-провайдера):

- **Email OTP Length: 4** (по умолчанию 6 — приложение ждёт 4).
- Email OTP Expiration: 3600 секунд достаточно.

## 3. Шаблоны писем

**Authentication → Emails → Templates.** Оба приложения используют один
проект, поэтому шаблоны общие. Кто какое письмо получает:

- **Confirm signup** — регистрация нового клиента в приложении (нужен код);
- **Magic Link** — повторный вход клиента (нужен код) И вход сотрудника в
  админку (нужна ссылка), поэтому в нём должно быть и то и другое.

### Confirm signup

Тема: `Код подтверждения — CLUB 40`

```html
<h2>Добро пожаловать в CLUB 40!</h2>
<p>Ваш код подтверждения:</p>
<h1 style="letter-spacing: 6px; font-size: 32px">{{ .Token }}</h1>
<p>Введите его в приложении. Код действует 1 час.</p>
<p style="color: #888">Если вы не регистрировались — просто игнорируйте это письмо.</p>
```

### Magic Link

Тема: `Вход в CLUB 40`

```html
<h2>Вход в CLUB 40</h2>
<p>Код для входа в приложение:</p>
<h1 style="letter-spacing: 6px; font-size: 32px">{{ .Token }}</h1>
<p>Введите его на экране входа. Код действует 1 час.</p>
<hr />
<p>Входите в админ-панель? Нажмите ссылку:</p>
<p><a href="{{ .ConfirmationURL }}">Войти в админ-панель</a></p>
<p style="color: #888">Если вы не запрашивали вход — просто игнорируйте это письмо.</p>
```

> Почему одно письмо на два случая: шаблон Magic Link общий для проекта.
> Полное разделение («клиенту — только код, сотруднику — только ссылка»)
> делается через Send Email Hook + edge-функцию с Resend API — могу собрать,
> когда появится Supabase access token.

## 4. Лимиты

**Authentication → Rate Limits**: с собственным SMTP лимит писем можно
поднять — поставьте разумное значение (например, 100/час). Дефолтный лимит
«2 письма в час» с дефолтного SMTP больше не действует, но проверьте, что
поле не осталось заниженным.

## 5. Проверка

1. Клиентское приложение → «Получить код» → письмо с noreply@base40.fit,
   4 цифры, вход работает; повторная отправка работает.
2. Регистрация нового email → письмо Confirm signup, после кода создаётся
   профиль (имя/телефон подтягиваются из формы).
3. Админка → пароль → письмо со ссылкой → клик → вход.
4. Письма не в спаме (если в спаме — проверить DKIM/SPF в Resend).

## Важное о безопасности (уже исправлено в коде)

Раньше OTP в клиентском приложении был бутафорией: код не проверялся, а вход
шёл по выводимому из email паролю — войти можно было под любым клиентом, зная
только его почту. Теперь вход только по настоящему коду из письма. После
проверки пункта 5 имеет смысл в Supabase → Authentication → Users глянуть,
нет ли подозрительных аккаунтов, созданных в период тестирования.
