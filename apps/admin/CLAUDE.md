# Base40 — админка (apps/admin)

Админ-панель фитнес-студии Base40. TanStack Start (SSR) + React 19 +
Tailwind 4 + shadcn/radix. Пакетный менеджер — bun.

Это часть монорепозитория: общие правила (рабочий режим, деплой, форматы
студий, **база данных и модель доступа**) — в корневом `CLAUDE.md`. Схема БД —
`db/` в корне репозитория. Клиентское приложение — `apps/client`.

## Команды (из apps/admin)

- `bun install` — зависимости (только публичный npm-реестр)
- `bun run dev` — дев-сервер на :8080
- `bun run build` — прод-сборка (Nitro node-server → `.output/server/index.mjs`)
- `bunx tsc --noEmit` — типы; должен быть чистым перед коммитом
- `bun test` — тесты (логика auth-писем, отправка почты, инструменты Kate,
  проверка телефона/email клиента; пакетные клубы — замены тренеров
  `lib/schedule-trainers.ts`, остаток на занятие `lib/booking-coverage.ts`,
  статус абонемента `lib/membership-status.ts`, роли `lib/staff-roles.ts`;
  пуши — шифрование и VAPID `lib/push/web-push.test.ts` по примеру RFC 8291,
  содержимое пуша `lib/push/payload.test.ts`, каталог триггеров
  `lib/push-triggers.test.ts`; вкладка «Приложение» карточки клиента —
  `lib/client-app.test.ts`).
  Файлы `*.test.ts` исключены из tsc: глобальные типы Bun конфликтуют с
  DOM-типами приложения.
- `bun run lint` — 0 ошибок (остаются 5 предупреждений react-refresh в
  shadcn-файлах); держать так. `eslint-disable` и `as any` в коде страниц нет —
  не добавлять. Форматирование и содержательные правки — разными коммитами.

## Деплой

Ресурс Coolify `club40-admin`, https://admin.base40.fit, Dockerfile —
`apps/admin/Dockerfile` (контекст — корень репозитория: нужен `db/`).
Env-переменные: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`
(build-time), `APP_SUPABASE_SERVICE_KEY` (runtime-секрет, раздел
«Доступы»), `DATABASE_URL` (runtime-секрет, прямое подключение к Postgres
для мигратора; не задан — миграции пропускаются). AI-переменные
(`AI_GATEWAY_*`, `AI_CHAT_MODEL`, `AI_TRANSCRIBE_MODEL`) не заданы — ассистент
и диктовка намеренно отвечают 503 до выбора провайдера. Пуши (необязательно):
`VAPID_SUBJECT` — контакт отправителя для служб доставки (по умолчанию
`mailto:noreply@base40.fit`), `PUSH_WORKER=off` — не рассылать с этого
сервера (и «Отправить сейчас» здесь очередь не толкает — заберёт сервер, где
рассылка включена).

## Auth-письма

Send Email Hook (`GOTRUE_HOOK_SEND_EMAIL_*` у сервиса auth): Supabase дёргает /api/auth-email (src/routes/api/auth-email.ts),
логика писем — src/lib/auth-email.ts (+ тест auth-email.test.ts), отправка —
src/lib/mail.ts с noreply@base40.fit через Resend (`RESEND_API_KEY`).
Решение владельца 2026-10-11 (позднее прежнего «остаёмся на Unisender Go»):
переходим на Resend, Unisender Go отключён, код Unisender удалён.

**Во всех письмах авторизации — 6-значный код, ссылок авто-входа нет**
(решение владельца 2026-10-10; recovery/invite — тоже код: `/recover` у GoTrue
публичный). Текст письма зависит от ПРИЛОЖЕНИЯ, а не от человека: один
человек может быть и админом, и клиентом. Признак — хост в redirect_to (оба
приложения задают emailRedirectTo явно): admin.base40.fit -> «вход в
админ-панель», всё остальное (включая нераспознанный redirect) -> клиентское
письмо. Код входа в клиентское приложение уходит только члену клуба — есть
карточка клиента с этой почтой (RPC `client_app_sign_in_allowed` сервис-ключом,
`needsClubMembership`); иначе хук отвечает GoTrue ошибкой `not_a_club_member`.
Env: SEND_EMAIL_HOOK_SECRET, RESEND_API_KEY,
опционально ADMIN_APP_URL и RESEND_RPS (runtime, Coolify). Настройка — AUTH_SETUP.md
в корне репозитория.

**Нагрузка** (2026-10-16, запуск приложений: ~1000 клиентов входят в одно
утро): GoTrue ждёт хук 5 секунд **на все свои попытки сразу**, поэтому хук
укладывается в 4,3 с (`HOOK_BUDGET_MS`): проверка карточки — не дольше 1,5 с,
письма — `sendMail(…, { deadline })`. Лимит Resend — запросов в секунду на
команду (10), сверх — 429: `sendMail` выстраивает письма в очередь (не чаще
`RESEND_RPS`, по умолчанию 8 в секунду) и повторяет 429 (кроме исчерпанной
квоты тарифа) и 5xx с паузой, пока успевает до deadline; таймаут и обрыв
связи не повторяет (письмо могло уйти — был бы второй код). Тесты —
`src/lib/mail.test.ts`. Объём писем ограничивают не код, а тариф Resend
(Free — 100 в сутки) и `GOTRUE_RATE_LIMIT_EMAIL_SENT` (в час на весь сервер)
— AUTH_SETUP.md, шаг 6.

**Письма Lady Stretch** (решение владельца 2026-10-15): клиенты пакетных
клубов (redirect_to — `app.lady-stretch.one` или `pack.base40.fit`, список —
`PACKAGES_APP_URLS`, `isPackagesApp`) получают письма в брендинге студий
растяжки — `emailBrand` → `"ladyStretch"`: светлое (решение владельца
2026-10-15, тёмное — «мрачно»): светло-серая подложка, белая карточка с
тёмной шапкой цвета меню `#1a2027` и белым логотипом
(`public/email/lady-stretch-logo-dark.png` — PNG: почтовики не показывают
SVG; грузится с `ADMIN_APP_URL`), текст и цифры кода — серый меню
`#1a2027`, код — на бледно-розовой плашке с розовой рамкой `#f763fc`. Вёрстка
таблицами с `bgcolor` — иначе почтовик, срезавший фон у div, потерял бы
тёмную шапку.
Отправитель — `emailSender`: `LADY_STRETCH_MAIL_FROM`
(`noreply@lady-stretch.one`, задаётся только после Verified домена в Resend —
AGENT_TASKS.md, Задача 13), без неё — `noreply@base40.fit` под именем
«Lady Stretch». Админка и app.base40.fit — Base40, как прежде; письмо входа в
админку — всегда Base40. Тексты пока только русские.

**Вход в админку — только по 6-значному коду из письма, паролей у
сотрудников нет** (решения владельца 2026-10-09, 2026-10-10). Форма /auth шлёт
почту в серверную функцию `requestStaffLoginCode` (src/lib/auth.functions.ts):
она сервис-ключом проверяет, что почта принадлежит сотруднику, и только тогда
просит GoTrue отправить код; ответ одинаковый для любой почты. Код создаёт
GoTrue и видит только хук писем — в браузер он не возвращается ни в каком
ответе (не логировать, не класть в URL/хранилище); введённый код браузер
отдаёт прямо в GoTrue (`verifyOtp`, type `email`). Пароли сотрудников стирает
`db/migrations/2026-10-10_staff_accounts.sql` (разово + триггер при выдаче роли): пароль давал токен
напрямую у GoTrue в обход письма. Сотрудники добавляются в «Доступах»: фамилия, имя, почта
и права (profiles.full_name = «Фамилия Имя»; есть учётная запись — только выдаётся доступ,
имя дописывается, если пустое). Роль сотрудника проверяет и guard
(\_authenticated/route.tsx).

## Код

- Клиент Supabase в браузере НЕтипизированный (без `<Database>`); свежие типы
  генерировать пока нечем — нужен access token владельца.
- Стиль: русские тексты UI, `@/` алиасы. Иконки — **Hugeicons** под именами
  lucide: alias в `vite.config` + `paths` в `tsconfig` подменяют
  `lucide-react` на шим `src/lib/icons.tsx` (сам пакет `lucide-react` из
  зависимостей убран). Шим генерируется — `bun run scripts/gen-icons.ts`
  пересобирает его по фактическим импортам; ручные соответствия имён лежат
  в `MANUAL` там же. Исключение — иконки бокового меню: Solar (Outline, у
  активного пункта — BoldDuotone) в `components/nav-icons.tsx`, генерируются `bun run scripts/gen-nav-icons.ts`
  (пакет `@solar-icons/react` — только devDependency: в нём все 6 начертаний
  на иконку, напрямую он раздувал бандл на ~226 kB; координаты путей
  генератор округляет до сотых — минус треть файла).
- Цвета: основной цвет — токен `--brand` (`text-brand`, `border-b-brand`);
  в styles.css — розовый по умолчанию, при открытой студии его подменяет
  `studios.brand_color` (`components/studio-branding.tsx`),
  подложка рабочей области — `--canvas`, меню — `--sidebar`; всё в
  `src/styles.css`. `--primary` (тёмные кнопки, активный таб) — тот же цвет,
  что меню. Табы (`ui/tabs.tsx`) — общая плашка, переезжающая к активному
  табу; фон триггерам не задавать. Логотип в меню — `studios.logo_url`
  активной студии (бакет `studio-logos`; прежний Lady Stretch —
  `public/logos/lady-stretch.svg`). Меню всегда развёрнуто (ширина — SIDEBAR_WIDTH в
  `ui/sidebar.tsx`, включает рейку), свёрнутого режима нет.
- Слева от меню — рейка разделов `components/app-rail.tsx` (иконка + подпись,
  у активного — белая иконка с разноцветным свечением `rail-glow`; разделы и

  - тест): один клуб, несколько или все клубы ОДНОГО формата (аналитика

    PostgREST — 1000 строк на ответ), расчёты — `lib/dashboard-analytics.ts`
    (+ тест). История продаж выбранных клубов (продажи с платежами рассрочки, прочие
    продажи, возвраты) грузится целиком одним queryKey и считается в браузере:
    «Фактическая выручка» и платежи — поступившие деньги, как в зарплатах
    (без графика — вся сумма в день продажи, с рассрочкой — внесённые платежи
    по `paid_at`); новый / продление / возврат — по прошлым абонементам

    история от групповых, абонемент с возвратом — как отменённый); задолженность — без

    (действующий или замороженный абонемент, пробный не в счёт);
    «Занятия» (2026-10-14) — групповые занятия, которые уже начались и не
    отменены клубом (`loadClassEntries`: schedule_entries + тренеры + живые

    заполняемость (посещения / вместимость, занятия без лимита не в счёт),

### Слой данных (React Query)

- **Скелетоны**: пока данных раздела нет — болванка СВОЕЙ структуры
  раздела, а не пустота, «0», спиннер или чужая раскладка. У каждой страницы
  — свой `XxxPageSkeleton` в `src/components/page-skeletons.tsx` и
  `pendingComponent` в роуте (без него падает `src/lib/page-skeletons.test.ts`);
  его же показывают проверка прав, каркас до входа и `RequireFormat`.
  Меняешь раскладку страницы — правь и её скелетон. Пошагово и чек-лист —
  `.interface-design/system.md`, раздел «Скелетоны».
- Загрузка — `useQuery` + `unwrap()` из `src/lib/query.ts` (ошибка Supabase →
  исключение). Текст ошибки — `meta: { errorMessage: "Не удалось загрузить …" }`,
  тост показывает общий QueryCache — свой `toast.error` на загрузку не писать.
- queryKey: `[таблица, studioId, ...параметры]`. После записи —
  `invalidateQueries({ queryKey: [таблица] })`; локальная правка без
  рефетча — `setQueryData`. Кнопка «Обновить» в шапке инвалидирует весь кэш —
  отдельной «шины обновления» нет. Смена вошедшего пользователя (выход/вход)
  очищает кэш целиком (`__root.tsx`, `onAuthStateChange`): запросы со
  `staleTime: Infinity` (студии, права, профиль) иначе держали бы ответ,
  полученный без сессии.
- **Быстродействие (2026-10-11)** — не откатывать:
  - guard `_authenticated/route.tsx` (его `beforeLoad` идёт на КАЖДОМ
    переходе) ходит в сеть только при первом входе человека во вкладке
    (`getUser` и роль — параллельно), дальше — `getSession` без сети;
    там же заранее запускаются `studiosQuery`, `adminPermissionsQuery`,
    `staffProfileQuery` (опции запросов — в их хуках), чтобы меню и права не
    грузились по очереди после проверки;
  - код разделов: наведение на ссылку грузит чанк (`defaultPreload: "intent"`
    в `router.tsx`), а `usePreloadSections` после входа в простое грузит
    чанки всех открытых сотруднику разделов;
  - тяжёлое в общем каркасе — только `lazy`: Kate (AI SDK, markdown) в
    `admin-shell.tsx`, карточка клиента в поиске шапки (с ней формы и
    libphonenumber-js), графики дашборда (`components/metric-chart-plot.tsx`,
    `components/dashboard/plots.tsx`, recharts). Новое тяжёлое в шапку/меню/дашборд — тоже `lazy`; проверка —
    размер `admin-shell-*.js` в выводе `bun run build` (~90 kB, было 800);
  - `gcTime` — 30 минут (`lib/query.ts`): повторный заход в раздел
    показывает кэш сразу и обновляет его фоном;
  - сборка кладёт рядом с ассетами `.br`/`.gz` (`compressPublicAssets` в
    `vite.config.ts`).
- Серверная пагинация — `useServerTable` (`src/hooks/use-server-table.ts`):
  все фильтры в queryKey (строками, не объектами), смена фильтра сама
  возвращает на 1-ю страницу; подвал — `<DataPagination {...table.pagination} />`.
  Клиентская пагинация небольших списков — `usePagination`. Поиск —
  `useDebouncedValue` + `sanitizeSearch`.
- Студия — `useActiveStudioId()` (`src/hooks/use-active-studio.ts`), заглушка
  без студии — `<RequireStudio>`, страница одного формата студий —
  `<RequireFormat>` (STUDIO_FORMATS.md). Список студий сотрудника и активная студия с
  форматом/цветом/логотипом — `useStudios()` / `useActiveStudio()`
  (`src/hooks/use-studios.ts`). Серверным функциям и API-роутам активная
  студия уходит заголовком `X-Studio-Id`; сервер сверяет роль именно в ней
  (`getStaffStudio`), без заголовка — студия из профиля. Текущий сотрудник — `useStaffProfile()`;
  для записи в БД — `await ensure()` (иначе ранний клик пишет null).
- Диалог с формой: состояние формы — в дочернем компоненте внутри
  `<DialogContent>` с `key={item?.id ?? "new"}`, инициализация через
  `useState(item?.x ?? "")`. Эффекты «сбросить поля при открытии» не писать:
  Radix размонтирует содержимое при закрытии. Сначала валидация, потом
  `setSaving(true)`, снятие — в `finally`. Удаление — `useConfirm`.
- Разметка форм — блоки из `components/ui/form-field.tsx` (`FormField`,

  всех формах — решение владельца 2026-10-11): ровно те поля, без которых
  обработчик не сохранит форму; новое обязательное поле — сразу с `required`.
  Подсказка «?» у подписи поля — проп `tip` у `FormField`/`SwitchRow`: зачем
  поле, 1–2 предложения; новому неочевидному полю — писать сразу. Тот же

### Пуш-уведомления (рассылка, 2026-10-15)

Стандарт Web Push, сторонних сервисов нет: пуш уходит в службу доставки
браузера (Google — Android/Chrome, Apple — iOS 16.4+ у приложения «На экран
„Домой“»), служба — на телефон. Схема и очередь — корневой CLAUDE.md
(`2026-10-15_push_delivery.sql`), приём на телефоне — `apps/client/CLAUDE.md`
(«Пуш-уведомления»).

- Отправитель — фоновый цикл этого же сервера:
  `src/lib/push/push-worker.server.ts`, запуск — `src/server.ts` (без
  `APP_SUPABASE_SERVICE_KEY` не запускается). Раз в 15 секунд и сразу по
  «Отправить» (`kickPushQueue`, `lib/push.functions.ts`): наступившие
  запланированные → выборка и очередь (`push_start_due`), пачки по 200
  доставок, 25 запросов к службам параллельно (2000 телефонов — секунды),
  итог пачки — `push_finish_deliveries` (с повтором: не записанный итог
  вернул бы пачку в очередь, пуши ушли бы дважды). Очередь в базе:
  перезапуск посреди рассылки её не теряет, два контейнера при выкатке
  берут разные строки (`skip locked`). Ответ службы: 2xx — отправлено,
  404/410 — телефона больше нет (подписка удаляется), 429/5xx/сеть —
  повтор (до 5 попыток), прочее — «не дошло» (403 подписку НЕ удаляет:
  так отвечают и на ошибку подписи). Если повторов больше четверти пачки
  (служба перегружена), остальная очередь ждёт следующего прохода — иначе
  все 5 попыток сгорали бы за секунды.
- Шифрование (RFC 8291, aes128gcm) и подпись VAPID (RFC 8292, ES256) —
  `src/lib/push/web-push.server.ts`, только WebCrypto и fetch (без
  библиотек). Ключи VAPID — в базе (`push_vapid_keys`), нет — создаются при
  первом запуске; не менять и не удалять: все подписки телефонов привязаны к
  открытому ключу, с новым ключом пуши перестанут доходить до всех.
- Содержимое — `src/lib/push/payload.ts`: заголовок и текст на языке
  приложения на телефоне (язык → английский → русский, как в приложении),
  ссылка перехода (раздел `/schedule` или `https://…`; «schedule» → «/schedule»),
  иконка приложения формата (Android); не больше 3800 байт — длинный
  текст укорачивается (целиком он в ленте приложения), не влезла ссылка —
  пуш уходит без неё.
- Страница — `routes/_authenticated/push.tsx`: форма сохраняет
  запланированное (сейчас или на дату; «Отправить сейчас» — с
  подтверждением и числом получателей; время «сейчас» ставит база —
  `scheduled_at` null, часы компьютера могут спешить), охват — RPC `push_audience_stats`
  (в выборке / в приложении / с включёнными уведомлениями), пока идёт
  рассылка — список обновляется сам. Отправленное не правится — «Создать
  копию»; удаление отправленного убирает его и из ленты клиентов.
  Колонки: «Получатели» (клиенты с приложением и их телефоны),
  «Отправлено» (принято службой; «не дошло»), «Доставлено» (телефон
  показал), «Прочитано» (клиенты, открывшие пуш или уведомление в ленте).
  Триггерные (`trigger_key` не пуст) в списке не показываются.
- **Триггерные уведомления** (2026-10-15) — «Мобильное приложение» →
  «Триггеры», `routes/_authenticated/push-triggers.tsx`: автоматические
  пуши по событиям. У каждого приложения (формата) свой набор — при клубах
  обоих форматов сверху выбор приложения. Карточка триггера: когда уходит
  (с текущими параметрами), текст с подсвеченными переменными, флаги
  переводов, статистика за 30 дней (`push_trigger_stats`), включатель
  (сразу сохраняет) и «Изменить» — окно: включение, заголовок и текст на
  трёх языках (`useContentTranslations`, как у контента), переменные
  кнопками (вставка на место курсора), предупреждение о чужих переменных,
  пример «Как увидит клиент», параметры, ссылка перехода. Каталог (подписи,
  описание срабатывания, переменные, пределы параметров) —
  `lib/push-triggers.ts` (+ тест: ключи и стартовые тексты сверяются с
  миграцией); новый триггер = строка в каталоге + стартовые тексты и ветка
  в `push_triggers_run` новой миграцией. Триггеры: напоминание о занятии,
  «Вас записали» (записал не сам клиент), занятие отменено, замена тренера,
  абонемент оформлен / скоро закончится / закончился, рассрочка — скоро
  платёж / просрочен, давно не был, день рождения; только пакетные —
  мало тренировок, тренировки закончились, после пробной, оцените тренера.
  Проверку событий запускает тот же цикл рассылки раз в минуту
  (`push_triggers_run` в `push-worker.server.ts`; ошибка не мешает

## Известные недоработки (найдены при рефакторинге 2026-10-09, не исправлены)

Нужна миграция БД:

- Во вью `sales_list` и `bookings_log_full` нет `crm_link` — ссылки amoCRM
